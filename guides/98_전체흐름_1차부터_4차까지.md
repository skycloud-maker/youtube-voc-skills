# 2차 — 판독 (LLM 둘)

## 준비 — 실무자

```
어떤_폴더\
   ├ 판독A\   ← VoC_2_2차판독.zip 을 풀고, **1차 결과 엑셀을 이 안에** 넣기
   └ 판독B\   ← 〃
```

★ 엑셀은 **폴더 안에** 놓습니다. 채팅창 첨부가 아닙니다 — 판독자가 스스로 찾습니다.

★ 서로 다른 LLM 둘을 씁니다 (Claude Code · Codex). 같은 것을 둘 쓰면 같은 실수를 같이 합니다.

## 돌리기 — 실무자

```
① 각 폴더에서 AI 를 열고  프롬프트\0_붙여넣을_프롬프트_도구형.md
② 「full_NN 까지 했습니다」 하고 멈추면  프롬프트\0_붙여넣을_프롬프트_이어서.md
   ★ 53회차라 5~6번 되풀이합니다 (원문이 쌓이면 막히는 LLM 쪽 제약)
```

## 판독자가 스스로 돌리는 도구 — 무엇을 하나

| 도구 | 무엇을 하나 | 왜 있나 |
|---|---|---|
| `자가점검.py` | 시작할 수 있는 자리인가 · 판독자 폴더가 섞였나 | 남의 번들이 섞이면 결과가 뒤바뀐다 (겪었다) |
| `데이터_넣기.py` | 엑셀을 앉히고 회차로 나눈다 (120행씩) | 한 번에 다 주면 LLM 이 얕게 본다 |
| `build_bundle.py` | 회차마다 판정을 모아 번들을 만든다 | 판정 결과가 흩어지면 못 모은다 |
| `성실성검사.py` | 얕게 하지 않았나 · 적힌 시각이 누적인가 | 「다 했다」 고 하고 절반만 한 적이 있다 |
| `지문검사.py` | 도구·기준을 고쳤나 | 판독자가 조건을 바꾸면 둘을 견줄 수 없다 |
| `topic_registry.py` | 새 라벨이 흩어지나 · topic_group 이 붙었나 | 라벨 신설은 자유지만 흩어지면 집계가 갈린다 |
| `넘어가도_되나.py` | 다음 차수로 넘어가도 되는지 스스로 판단 | 안 끝났는데 넘기면 뒤에서 조용히 틀린다 |
| `handoff.py` | 보정요청서를 뽑는다 | 「담을 라벨이 없다」 를 버리지 않고 모은다 |

## 2차가 분리·병합도 한다

```
분리   한 댓글에 주제가 여럿이면 조각으로 나눈다  →  분리제안 시트
병합   1차가 잘못 쪼갠 것을 합친다 (structure.merge)
```

★ **1차 동결과 무관합니다.** 동결이 묶는 것은 엔진의 자동 분리 규칙이고,
  2차는 그 결과를 고칠 수 있습니다.

## 끝나면

```
판독A\_판독패키지\_결과\<이름>_bundle\    최종 번들
판독A\_인계\보정요청.csv                  기준서 빈 곳 · 엔진 결함
```

★ **두 폴더를 그대로** 총괄에게 넘깁니다. 번들만 떼어 옮기면 보정요청이
  빠집니다 (실제로 3건이 사라졌습니다).

★★ **익명화는 총괄이 해야 진짜입니다.** 감독자가 만들면 2차 결과를 봐야 하고,

# 3차 — 감독 (LLM 둘)

## 받는 것 — 실무자

총괄이 차려 준 폴더 둘을 그대로 받습니다. **폴더를 만들 일도, 2차 폴더를 옮길 일도 없습니다.**

★ 3차 감독 zip 만 풀어서는 시작할 수 없습니다 — `judge_input.csv` 가 총괄 손에서 나옵니다.

## 돌리기 — 실무자

```
① 각 폴더에서 **새 채팅**을 열고  프롬프트\0_붙여넣을_프롬프트_감독.md
   ★ 2차를 돌린 그 세션에 붙이면 안 됩니다 — 자기 답을 편듭니다
② 「judge_NN 까지 했습니다」 하고 멈추면 **같은 프롬프트를 다시**
   ★ 12회차라 1~2번이면 됩니다
```

## 감독자가 보는 것 · 내는 것

```
[보는 것]  atomic_id · product · voc_cleaned · atomic_voc
           ★ original_voc     원문 전체 (atomic 은 그 조각이다)
           ★ parent_voc       답글이면 부모 댓글
           ★ video_title      어느 영상인가
           ★ 이_원문의_조각수   과소·과분리를 보는 자리
           A · B              두 판독자의 답 (누구 것인지는 모른다)

[내는 것]  A   A 가 맞다
           B   B 가 맞다
           C   둘 다 아니다 — 직접 답을 내고 이유 한 줄
           D   ★ 둘 다 맞다 — 나눠야 한다 (또는 merge — 과분리다)
```

★ `D` 는 2026-08-25 에 넣었습니다. 4차에서 **69행 중 11행이 「둘 다 맞다」**
  였는데, 말할 칸이 없어 억지로 하나를 골랐고 그래서 사람 일감이 됐습니다.

## 감독자가 돌리는 도구

| 도구 | 무엇을 하나 |
|---|---|
| `자가점검.py` | 시작할 수 있는 자리인가 · 감독할 것이 있나 |
| `감독_읽기.py` | 한 회차(145행)만 꺼내 읽는다 — 한꺼번에 주면 얕아진다 |
| `성실성검사.py` · `지문검사.py` | 얕게 하지 않았나 · 도구를 고쳤나 |
| `넘어가도_되나.py` | 판정이 회차 수만큼 있나 · **모든 행**에 답이 있나 |

## `3차_마무리` 가 하는 열한 가지

| | 단계 | 무엇을 · 왜 |
|---|---|---|
| ① | 감독 결과를 모은다 | 두 폴더를 찾아 판정 파일을 읽는다. 옛 이름(`심판결과_*`)이 오면 스스로 바꾼다 |
| ② | 전 회차를 마쳤는가 | **파일 이름으로 센다** — 같은 파일을 두 곳에서 찾아 두 번 센 적이 있다 (「24회차」) |
| ③ | 통합 `build_master` | 판독자 합의 + 감독 판정을 반영. 감독이 갈리면 **사람이볼목록**으로 |
| ④ | 스스로 검사 `check_selfcheck` | ✗ 0건이어야 다음으로 |
| ⑤ | 보정요청 `handoff` | 2차 것까지 이어받는다. 해소된 것은 접어 두되 없애지 않는다 |
| ⑥ | 개선 우선순위 `rank_two_axis` | 두 축 — 건수 / 부정 강도 |
| ⑦ | **편향검사** | ★ 감독자가 자기 편을 들었나. **총괄이 잰다** (아래) |
| ⑧ | `PL이슈_뽑기` | 안전·위생을 건수와 무관하게 전량 |
| ⑨ | `시트_붙이기` | xlsx 에 ★사람이볼목록 · ★보정요청 · ★PL Issue |
| ⑩ | `보정요청_논의본` | 회의에서 같이 보고 정할 글 |
| ⑪ | `_최종결과\` 에 받을 것만 모은다 | 실무자가 열 파일만 남긴다 |

★ 그 밖에 **자물쇠**가 걸려 있습니다 — 두 사람이 동시에 통합하면 결과가
  엉킵니다. 30분 안에 다시 돌리면 「지금 누가 돌리는 중입니다」 하고 멈춥니다.

## ★ 편향검사는 왜 3차가 아니라 여기인가

```
감독자가 스스로 재면   자기 답이 어느 쪽인지 알아야 잴 수 있다
                     → 알면 편들게 된다. 익명화가 깨진다
총괄이 재면          정답지(ab_mapping)를 총괄만 갖고 있으니 잴 수 있다
                     → 감독자는 끝까지 모른 채로 있다
```

★ 그래서 **감독 폴더에는 편향검사가 아예 없습니다.** 총괄 자리에서만 돕니다.
  실측 — claudecode 57.3% · codex 51.5%. 치우침이 없다는 뜻입니다.

★ 반려하지 않고 **알림만** 합니다. 편향이 보여도 판정을 되돌리지 않고
  「이런 기울기가 있었다」 를 남깁니다.
