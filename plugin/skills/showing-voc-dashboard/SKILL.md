# 대시보드 보여 주기 (VoC 최종 산출물)

★ **자료가 없으면 달라고 한다 — 사용자 폴더를 뒤지지 않는다.**
  바탕화면 · 문서 · 다운로드처럼 사람의 개인 폴더를 찾아보지 않는다. 어느 파일이 필요한지
  말하고 기다린다 (2026-10-20 실제 AI 시험에서 파일이 없을 때 그 세 폴더를 뒤졌다).

이 스킬은 **이미 나온 최종 산출물을 보여 주는 일**뿐이다. 판정하지 않고, 숫자를 새로 세지 않는다.

★ 숫자는 **엔진의 계산을 그대로 부른다** — `data_contract` · `scoring`.
  우리가 따로 세면 Streamlit 대시보드와 숫자가 갈린다 (공통 규칙 6).

★ **라이브만 안 된다.** 유튜브에서 새로 모으고 다시 분석하는 것(OpenAI 호출)은 서버가 있어야 한다.
  보는 것(표 · 그림 · 탭 · 찾기 · 정렬)은 HTML 안에서 다 된다 — 인터넷이 없어도 열린다.
  sky 2026-10-20 — 「어차피 라이브로 하면 외부망을 써야하는데 그건 어려우니 … 차라리 결과물 나온 걸
  가지고 html 로 개인이 열어서 볼 수 있도록 하는 게 맞지 않나」.

## 차례

1. **무엇을 받았는지 본다.** 4차까지 거친 **최종 엑셀**(`voc_dashboard_export_bundle_*.xlsx` ·
   `raw_voc` 시트가 있는 것)이 있어야 한다. 없으면 **만들지 않고** 무엇이 필요한지 말한다 —
   빈 화면을 만들어 놓고 됐다고 하지 않는다.

2. **HTML 한 장으로 만든다** (이게 기본이다).

   ```bash
   python <이 스킬>/scripts/대시보드_HTML_만들기.py <최종엑셀> [<받을곳>]
   ```

   나오는 것 두 벌 — sky 2026-10-20 「둘 다 필요하다」

   | 파일 | 누가 보나 | 담는 것 |
   |---|---|---|
   | `<이름>_살펴보기.html` | 사내에서 본다 | 원문이 들어 있다 |
   | `<이름>_공유용.html` | 밖으로 보낼 때 | 원문 전량을 빼고 링크·이메일·사용자명을 치운다 · 유튜브 댓글 id 는 **가명**(`댓글#1` 꼴)으로 바꾼다 |

   ★ 공유용은 **치운 건수를 적고 다시 훑어 0건임을 확인**한다 (`building-voc-report` 와 같은 규율).
   ★ 식별자를 **지우지 않고 가명으로** 바꾸는 까닭 (sky 2026-10-26) — `source_id` 는 영상별 댓글 수의
     분모이고 `atomic_id` 는 2차 분리 관계를 셈한다. 지우면 그 숫자가 깨진다. 같은 댓글은 늘 같은
     가명이라 셈은 그대로 되고 유튜브로는 되짚을 수 없다. 영상 id 는 공개된 값이라 그대로 둔다.
     남으면 종료코드 2 로 끝난다 — 그때는 **밖으로 보내지 않는다.**

3. **Streamlit 화면도 띄워야 하면** (사내에서 라이브로 만져 볼 때만)

   ```bash
   python <이 스킬>/scripts/최종본_앉히기.py <자리> <최종엑셀>
   python <이 스킬>/scripts/대시보드_띄우기.py <자리>
   ```

   또는 한 번에 — `대시보드_띄우기.py <자리> --최종 <최종엑셀>`

   ★ `<자리>` 는 **저장소 밖의 빈 폴더**다. 플러그인 안을 주면 멈춘다 —
     대시보드는 자기 폴더 아래에 쓰므로 엔진 사본이 더러워진다 (2026-10-08 에 겪었다).

## 왜 「앉히기」 가 따로 있나

대시보드는 `outputs/voc_dashboard_60/<이름>/voc_dashboard_dataset.csv` 를 **스스로 찾아** 띄운다
(`data_contract.latest_dataset` — glob 이 `*/…` 라 **한 겹**이다). 1차 결과는 거기에 떨어지니 자동으로 뜬다.

그런데 **최종 엑셀은 그 자리에 없다.** 사람이 화면의 「결과 파일 올려서 보기」 에 올리고
「이 파일로 화면 바꾸기」 를 **한 번 더 눌러야** 바뀐다 (그 패널이 쓰는 `app_runs/<id>/` 는 **두 겹**이라
스스로 못 찾는다). `최종본_앉히기.py` 가 그 두 번의 클릭을 없앤다 — 1차와 **같은 한 겹 자리**에 앉힌다.

판별은 **엔진의 함수를 그대로 쓴다** (`_read_analyzed_result_file` · `_validate_analyzed_result_frame`).
우리가 따로 판별하면 대시보드와 기준이 갈린다.

## 하지 않는 것

- **판정하지 않는다.** topic · 감성 · RootCause 를 새로 매기지 않는다. 최종본에 있는 값을 옮긴다.
- **숫자를 새로 만들지 않는다.** 엔진 계산 모듈이 낸 값만 쓴다.
- **라이브 재분석을 흉내내지 않는다.** HTML 에서 「다시 분석」 버튼을 만들지 않는다.
- **공유용에 원문을 남기지 않는다.** 다시 훑어 0건이 아니면 내보내지 않는다.

## 바깥에서 와야 하는 것

```
python 3.11+
pandas · openpyxl            최종 엑셀을 읽는다 (HTML 만들기에 필요)
streamlit                    3번(화면 띄우기)에만 필요하다. HTML 만들기에는 필요 없다
```

★ API 키는 **필요 없다.** 이 스킬은 이미 나온 결과만 본다 — 유튜브도 OpenAI 도 부르지 않는다.

## 어느 파일을 언제 여나

| 언제 | 무엇 |
|---|---|
| 화면이 무엇을 보여 주는지 알아야 할 때 | 엔진의 `src/dashboard60/views/` 다섯 (overview · improvement · inquiry · pl_issue · video) |
| 숫자가 어떻게 나오는지 | 엔진의 `src/dashboard60/data_contract.py` · `scoring.py` |
| 개인정보를 어디까지 치우나 | 공통 자리의 `shared/common/65_개인정보_처리_기준_및_제출문안.md` |
| 최종 산출물의 시트가 무엇인가 | 최종 엑셀의 `0_차례` 시트 |
