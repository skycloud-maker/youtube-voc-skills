# 3. 환원 규칙

## 3.1 [A] 라벨 — `content.verdict → topic`

| verdict | topic 처리 | 비고 |
|---|---|---|
| `Confirmed` | 현재값 유지 | 변경 없음 |
| `Relabel` | `proposed_label` 로 교체 | 캐노니컬 48 검증 |
| `Unclassifiable` | `미분류` 또는 `기타(제품군)` | `proposed_label` 을 따름 |
| `NotVoC` | `N/A` | ★ 되돌릴 수 없는 변경 |
| `Indeterminate` | 현재값 유지 | 사람 검토 대상으로 표시 |

```
★ NotVoC 자동 적용 여부는 §4 결정 1
  1차에서 자동 N/A 전환이 실질 VoC 를 삭제한 사고가 있었다
```

## 3.2 [B] 귀속

```
product_category   attribution.product_category 가 다르면 교체
                   category_changed 가 true 인 경우만
entity_role        attribution.entity 를 매핑

  confirm    → product_brand
  competitor → competitor_brand
  compare    → ★ 66컬럼 Enum 에 없는 값이다 (§4 결정 2)
  unknown    → unknown
```

```
★ ENUM_COLUMNS['entity_role'] = product_brand · competitor_brand ·
  creator_channel · unknown
  기준서 §3.3.2 의 compare 를 담을 칸이 없다
```

## 3.3 [C] 행 구조 — 가장 위험한 부분

### 분리하지 않은 행 (`split: false`)

```
행 수 변화 없음. 66컬럼 그대로 두고 topic 만 [A] 로 갱신
```

### 분리한 행 (`split: true`)

```
1행 → N행. 각 조각이 한 행이 된다

컬럼 성격별 처리

  source 수준 (19개)          전부 복사
    source_id · raw_row_index · parent_voc_id · comment_relation ·
    original_voc · voc_cleaned · voc_residual · reference_brand ·
    market · language · source_context_summary · status ·
    scope_exclusion_reason · proposal_flag · video_id · video_title ·
    video_url · product_category · product_category_source
    ★ voc_residual 은 재계산한다 (§3.4)

  atomic 식별                  새로 부여 (§3.4)
    atomic_id · atomic_index

  atomic 본문
    atomic_voc                 segment.text
    atomic_voc_summary         ★ 비움 (§4 결정 3)

  판정값
    topic                      segment.label
    topic_provisional          ★ 비움 — 1차 서술이며 조각과 대응하지 않는다
    topic_evidence             segment.quote 로 채운다

  1차 생성 근거 (rootcause 4종)
    rootcause_problem/target/cause/summary   ★ N/A (§4 결정 3)
    근거   R14 "Root Cause 는 결핍 서술이 있을 때만 산출"
           2차 판독은 이를 판정하지 않았다. N/A 가 규칙에 맞다

  점수 (tee 4종 · rootcause_score · topic_score · voc_total_score)
    ★ 0 또는 재계산 (§4 결정 3)

  나머지 (cej · inquiry_* · need_signal_* · confidence_* · entity_role 등)
    ★ 비움 또는 Enum 기본값 (§4 결정 3)

  trace_summary                "split_from: {원본 atomic_id}" 로 대체
```

### 병합한 경우

```
현재 기준서 §3.1 은 병합 출력을 정의하지 않는다.
과분리 행을 합치는 경우가 나오면 v0.2 에서 다룬다
```

## 3.4 `atomic_id` · `atomic_index` · `voc_residual` 재계산

```
atomic_id      {source_id}-{NN}   NN 은 source 내 순번 2자리
               ★ 분리로 순번이 밀리면 기존 행의 atomic_id 도 바뀐다
               → 1차 산출물과의 대조가 끊긴다
               → split_origin_atomic_id 에 원본 id 를 남긴다

atomic_index   source 내 등장 순서로 재부여

voc_residual   voc_cleaned 에서 모든 atomic_voc span 을 뺀 나머지
               ★ source 단위로 재계산한다. 조각이 늘면 residual 이 준다
               ★ 보존식 검증: voc_cleaned ≈ Σ atomic_voc + voc_residual
```

## 3.5 [D] 2차 전용 컬럼 — 66컬럼 뒤에 붙인다

```
na_class                  정당 N/A 판별 결과
qc_status_summary         PASS · RELABELED · SPLIT · FLAGGED · NOT_VOC
qc_rule_ids               적용된 과제 (A/B/C/D)
split_origin_atomic_id    분리 전 atomic_id. 미분리는 빈 값
secondary_topic_source    first_pass · secondary_read

신규 제안
qc_confidence             판독자 confidence
qc_evidence_status        과제 D 결과 (grounded/partial/ungrounded/conflict)
qc_exception_applied      정상 예외 번호

★ 42번 §9.3 이 앞 5종을 이미 규정했다. 뒤 3종은 신설 제안이다
★ 판정 전문(rationale · criteria_gap · label_gap)은 컬럼이 아니라
  qc_log.jsonl 에 남긴다. 번들에는 넣지 않는다
```

# 4. ★ sky 결정 대기 3건

## 결정 1 · `NotVoC` 판정을 번들에 자동 반영할 것인가

```
안 A  자동 반영    topic 을 N/A 로 바꾼 번들을 만든다
      위험   1차에서 자동 N/A 전환이 실질 VoC 를 삭제한 사고가 있었다
             (P-1 AUTO 14건 중 4건 오보정)

안 B  표시만      topic 은 유지하고 qc_status_summary 에 NOT_VOC 로 표시
      대시보드가 그 열로 필터할 수 있다
      되돌릴 수 있다

안 C  두 벌 산출   원본 유지 번들 + 반영 번들
      비교가 가능하다. 파일이 2배

권고   안 B → 사람 검수 후 안 A
```

## 결정 2 · `entity = compare` 를 어디에 담을 것인가

```
문제   기준서 §3.3.2 는 compare 를 판정값으로 두는데
       66컬럼 entity_role Enum 에 그 값이 없다
       (product_brand · competitor_brand · creator_channel · unknown)

안 A  compare 를 unknown 으로 접는다        정보 손실
안 B  2차 전용 컬럼 qc_entity 에 따로 담는다  66컬럼 불변 · 대시보드는 못 봄
안 C  Enum 에 compare 를 추가한다            ★ 66컬럼 계약 변경. 금지 사항

권고   안 B
```

## 결정 3 · 분리로 생긴 새 행의 1차 생성 필드를 어떻게 할 것인가

```
안 A  원본 값 복사      틀린 근거가 복제된다. 과제 D 가 지적한 문제를 증식시킴
안 B  비움 / N-A / 0    ★ 근거 규율에 맞다
                        단 rc_coverage · priority_score 등 파생 지표가 낮아진다
                        분리된 행이 우선순위에서 밀린다
안 C  판독자가 조각별로 재생성   가장 정확하나 판독 부담이 크게 늘고
                              1차 생성문을 2차가 다시 만드는 구조가 된다

권고   안 B + 파생 지표 영향을 별도 기록
       근거   R14 · R17 이 이미 "근거 없으면 N/A · 0 리셋" 을 규정한다
       ★ 단 이 선택은 improvement_priority 시트의 순위를 바꾼다.
         분리 전후 순위를 병기해 영향을 드러낼 것
```
