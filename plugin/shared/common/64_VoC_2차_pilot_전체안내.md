# VoC 2차 판독 pilot — 전체 안내

> **여기부터 읽으십시오.** 이 프로젝트의 모든 문서가 어디 있고 무엇을 위한 것인지 적혀 있습니다.
> 기준 2026-08-19 · pilot 1차 완료

---

## 0. 이 프로젝트가 무엇인가

유튜브 리뷰 영상의 **고객 댓글을 개선 과제로 바꾸는 일**을,
사람이 전부 읽지 않고도 할 수 있게 만든 것입니다.

```
댓글 1,570건
   1차  분석 엔진 (기계 규칙)        66컬럼을 채운다
   2차  판독자 LLM 둘               ★ 원문을 직접 읽고 다시 판정한다
   3차  감독자 LLM 둘               ★ 갈린 것만 A·B 익명으로 다시 본다
   4차  사람                        ★ 끝까지 갈린 것만 본다

결과   1,698행 · 라벨 1,185 (69.8%) · 사람이 본 행 186 (11.0%)
```

**핵심은 「둘」이 두 번 나온다는 것입니다.** 하나씩이면 그냥 네 번 돌린 것이고,
맞는지 알 방법이 없습니다.

## 2. 역할이 셋으로 갈려 있습니다 ★

이 프로젝트가 굴러간 것은 총괄과 실시간으로 협상했기 때문입니다.
**그건 실무 운영에서 못 합니다.** 그래서 이렇게 갈랐습니다.

```
판독자 (1~3차)   판정만 한다.
                 규칙이 없으면 「없다」 고 적고 넘어간다. 고치지 않는다

실무자 (4차)     최소한의 판단만 한다 — 「이건 X, 맞는 건 이것」
                 그리고 보정요청서를 총괄에게 전달한다

시스템 담당자     규칙·코드·기준서를 고친다. 다음 판에 반영한다
```

**보정요청서가 그 통로입니다.**

```bash
python handoff.py
```

```
_인계/보정요청.csv     ★ 이 파일이 시스템 담당자에게 갑니다
                       「어디를 손대야 하나」 로 묶여 있습니다
_인계/1~4차_인계서.md   각 차수가 다음 차수에게 무엇을 어떻게 넘기는지
```

### 사본에 대해

`_판독패키지/` 안의 파일 9개는 **루트 문서의 사본**입니다.
판독자에게 한 폴더로 건네려고 복사해 둔 것이라 **같은 내용입니다.**

```
11_택소노미        = _판독패키지/2_택소노미.md
21a·21b 기준문서   = _판독패키지/1a_·1b_
22_확장부록        = _판독패키지/4_2차_확장부록.md
24_도구형 프롬프트  = _판독패키지/0_붙여넣을_프롬프트_도구형.md
25_·26_·27_       = _판독패키지/6_·8_·9_
```

**고칠 때는 둘 다 고쳐야 합니다.** 패키지 쪽만 고치면 다음 회차에 옛 내용이 갑니다.
