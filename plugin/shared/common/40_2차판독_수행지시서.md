## 1. 어느 칸을 누구 것으로 쓰는가  ★ 이 판의 핵심

| 칸 | 정본 | 근거 |
|---|---|---|
| `topic` · `status` · `scope_exclusion_reason` | **감독자** | 두 판독자가 갈리면 감독자가 A/B/제3의 답으로 정한다 |
| `topic_evidence` | 그 라벨을 낸 **판독자** | 라벨과 근거는 짝이다. 라벨이 바뀌면 근거도 그쪽 것을 가져온다 |
| 서술 칸 전부 | **판독자 2 (CC)** | 아래 §2 |
| 조각 나누기 (`atomic_id`) | **판독자 2 (CC)** | 두 판독자의 분리가 달라 조각 id 가 갈렸다. 한쪽으로 통일해야 한다 |
| `product_category` | **제품군 확인 회차** | 개선 우선순위 표를 제품군별로 가르는 칸이라 틀리면 줄 전체가 틀린다 |
| `confidence_*` · `voc_total_score` · `validity` 등 | **기계** | 판독자가 채우면 안 된다. 후처리 계산값이다 |

### 서술 칸 목록

```
rootcause_problem · rootcause_target · rootcause_cause · rootcause_summary ·
rootcause_score · atomic_voc_summary · tee_summary · cej_evidence ·
tee_*_evidence · tee_*_score · need_signal_* · inquiry_* · cej · entity_role · brand
```

## 2. 왜 서술 칸을 판독자 2 것으로 정했는가

**눈으로 고르지 않았습니다. 두 가지를 쟀습니다.**

### ㉠ 틀 찍기 — 뼈대 고유비율

인용·숫자를 걷어낸 **뼈대**로 비교합니다. 통짜 문자열로 재면 속습니다.

```
                        판독자 1     판독자 2
   rootcause_problem      11%        100%
   topic_provisional      16%         63%
   tee_summary            59%         83%
   cej_evidence           76%         83%

★ 판독자 1 은 인용을 앞에 붙이고 뒷문장은 36종만 돌려썼다.
  "…에 대한 답을 외부에 묻고 있어, 사전 안내가 충분하지 않았음을 알 수 있다" 가 156회
```

### ㉡ 익명 감독자 — 원 판독자 채택률

두 답을 **A / B 로 익명화하고 행마다 무작위로 섞어** 감독자에게 줬습니다.
감독자는 어느 쪽이 자기 것인지 알 수 없습니다.

```
   감독자가 판독자 1 일 때   판독자1 답 39% · 판독자2 답 61%
   감독자가 판독자 2 일 때   판독자1 답 37% · 판독자2 답 63%

★ 감독자가 누구든 판독자 2 답을 1.6배 더 골랐다.
  판독자 1 이 감독자일 때도 자기 답을 39% 만 골랐다
```

**이 두 값이 같은 방향이라 결정할 수 있었습니다.** 하나만으로는 부족합니다.

## 3. 회차 순서

```
1  전량 판독        판독자 2명 × 1,570행           각 6~8시간
2  재분류           라벨 없는 행 + 제외 행 654행    ★ 「미분류」 를 없앤다
3  감독자             갈린 578행 × 감독자 2명           A/B 익명화
4  제품군 확인       본문과 category 가 어긋난 52행
5  근거 재작업       라벨이 바뀌어 인용이 안 맞는 행
6  ★ 사람 채점       감독자끼리 갈린 153행
```

### 회차마다 지키는 것

```
· 회차마다 파일을 따로 쓴다. 세션이 끊겨도 거기까지 남는다
· 회차 끝날 때마다 게이트 3종을 돌린다
    check_submission.py · topic_registry.py · topic_registry.py --register
· 새 라벨을 냈으면 --register 를 반드시 돌린다. 안 하면 계약 검증이 반려한다
```

## 4. 판정 규칙 — 회차를 넘어 유지되는 것

### 4.1 모든 행은 제외 아니면 라벨이다

```
「미분류」 도 「N/A」 도 남기지 않는다.
topic 은 열린 어휘라 마땅한 라벨이 없으면 새로 내면 된다.
그러니 「마땅한 라벨이 없다」 는 미분류의 이유가 되지 못한다.

주제가 있다  →  라벨을 낸다 (없으면 새로 만든다. 「기타」 로 도망가지 않는다)
주제가 없다  →  제외한다. 사유를 적는다
```

### 4.2 근거는 원문에서 문자 그대로 뽑는다

```
✅  "가격이 심각함"              원문에 그 글자 그대로 있다
❌  "가격에 대한 불만을 표현"      설명문이다
★ 억지로 뽑은 인용은 빈칸보다 나쁘다. 없으면 no_evidence 로 낸다
```

### 4.3 해석 여지 (`rootcause_problem`)

```
판별 둘. 둘 다 통과해야 한다
  ㉠ 원문을 정리해 옮긴 것이 아닌가
  ㉡ ★ 이 문장이 이 원문에서만 나올 수 있는 문장인가
     다른 원문에 갖다 붙일 수 있으면 여지가 아니다
```

### 4.4 `rootcause_cause` 가 비어 있는 것은 결손이 아니다

```
원문에 원인이 안 적혀 있으면 비운다. 채우면 지어낸 것이 된다.
대신 rootcause_summary 에 등급을 적는다
   L3  문제·대상·원인이 모두 원문에 있다
   L2  문제와 개선 대상은 있으나 원인 서술은 원문에 없다
   L0  해석 여지는 있으나 원문에 결핍 서술이 없다
★ 실측 — 원인이 빈 661행 중 93%가 등급으로 설명돼 있었다
```

### 4.5 이미 정해진 판단 (회사 결정)

```
종료 멜로디 「한국인은 안 기다린다」 류 문화 차이 잡담   → 제외
멜로디 길이·꺼짐·알림 방식에 대한 불만·개선 의견        → 알림·사운드
리뷰어가 제휴 고정 댓글에 쓴 제품 평가                  → operator_notice
                                                     ★ 고객의 소리가 아니라 광고다
시청자가 AI 요약을 통째로 붙여 넣은 댓글                → video_transcript (신설)
                                                     ★ 남기면 topic 집계가 영상 대본으로 부푼다
대상 제품군 밖 가전 (스타일러 · 무선청소기 등)          → 살린다
                                                     ★ 「다중가전」 은 가전 전반을 뜻한다
```

## 5. 사람에게 무엇을 올리는가

```
★ 행 단위로 올리지 않는다. 묶음으로 올린다
★ 「무엇을 확인해야 하는가」 를 반드시 적는다. 없으면 반려
★ 상한 — 묶음 10개 · 올린 행이 대상의 20% 를 넘지 않는다
   넘을 것 같으면 행을 보내지 말고 「무엇이 판단을 막았는지」 를 적는다.
   그건 기준서에 구멍이 있다는 뜻이라 규칙으로 메울 일이다

★ 「혹시 모르니 다 봐 달라」 는 하지 않는다
   실측 — review_required 가 89% 였던 판이 있었다. 아무것도 안 알려 준 것과 같다
```

## 6. 검사 — 눈으로 확인하는 자리를 없앤다

`check_selfcheck.py` 를 번들마다 돌립니다. **새 실수가 나오면 여기에 검사를 하나 더 붙입니다.**

```
S-1  틀 찍기       인용·숫자를 걷어낸 뼈대로 비교. 통짜 비교는 속는다
S-2  파일 안정     mtime 60초 이내면 「쓰는 중일 수 있다」
S-3  판정 병합     한 행에 판정이 둘이면 칸 단위로 합쳐졌는가
S-4  지표 정의     행의 갈래는 kind() 한 함수로만 낸다
S-5  근거 실재     인용이 원문에 있는가
S-6  1차 잔재      엔진이 쓴 서술이 남았는가
S-7  판정 유무     해석은 있는데 등급도 원인도 없는 행
```

### 지금까지 잡힌 내 실수 — 같은 걸 다시 짜지 않기 위해

```
· 통짜 문자열로 고유비율을 재서 100% 로 읽었다. 실제 뼈대는 36종이었다
· 공백을 무시하고 부분문자열을 봐서 계약 위반을 통과시켰다
· 파일을 쓰는 중에 읽고 「25행에서 멈췄다」 고 보고했다. 실제 114행이었다
· 판정 파일을 합칠 때 나중 것이 앞 것을 통째로 덮어 316행이 제외에서 풀렸다
· 일치율 계산을 회차마다 다시 짜서 64.4% 로 냈다. 실제 81.2% 였다
· 어휘 검색이 헐거워 후보를 세 번 부풀렸다
```
