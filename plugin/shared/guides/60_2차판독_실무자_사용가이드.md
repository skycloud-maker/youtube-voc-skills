# 2차 LLM 판독자 — 실무자 사용 가이드

> **이 문서를 읽는 사람** — 유튜브 VoC 분석을 실제로 돌리는 총괄
> **걸리는 시간** — 준비 10분 · LLM 작업 6~8시간 × 2 (기다리기만 하면 됩니다) · 확인 10분
> 기준 2026-08-19 · pilot 1차 완료본

---


## ★ 2026-08-23 부터 달라진 것 — 여기부터 읽으십시오

### 폴더를 이렇게 둡니다

```
어떤_폴더\
   ├ 판독A\   ← VoC_2_2차판독.zip 을 풀고, **1차 분석 엑셀을 이 안에** 넣기
   └ 판독B\   ← 〃
```

★ 엑셀은 **폴더 안에 놓으십시오.** 채팅창에 첨부하지 않아도 됩니다 —
  판독자가 폴더를 뒤져 스스로 찾습니다.

### 프롬프트가 둘입니다

```
① 프롬프트\0_붙여넣을_프롬프트_도구형.md    처음에
② 프롬프트\0_붙여넣을_프롬프트_이어서.md    「full_NN 까지 했습니다」 하면
```

★ ②는 **5~6번** 씁니다. 53회차라 한 번에 안 끝납니다.
  회차 번호를 적을 필요가 없습니다 — 판독자가 세어서 스스로 압니다.

### 끝나면 이 폴더를 3차로 **통째로** 넘깁니다

```
판독A\ · 판독B\ 를 3차 폴더 옆에 그대로 두십시오.
번들만 떼어 옮기면 보정요청이 빠집니다 (실제로 3건이 사라진 적이 있습니다).
```

## 0. 한 줄로

**1차 분석 엔진이 채운 데이터를, 서로 다른 LLM 두 개가 원문을 직접 읽고 다시 판정합니다.**
둘을 돌리는 이유는 하나입니다 — **답이 갈리는 곳이 곧 사람이 볼 곳**이기 때문입니다.

```
LLM 하나만 돌리면    답이 맞는지 알 방법이 없습니다
LLM 둘을 돌리면      같은 답 = 믿는다 / 다른 답 = 사람이 본다
```

## 1. 준비

### 1.0 ★ 「폴더를 AI 에게 열어 준다」 가 무슨 뜻인가

판독자 AI 는 **여러분 컴퓨터의 폴더 하나를 작업장으로 삼아** 일합니다.
그 작업장을 정해 주는 것이 「열어 준다」 입니다. 두 가지 방법 중 편한 쪽으로 하십시오.

#### 방법 ① — 폴더에서 바로 열기 (권장)

```
1. 파일 탐색기에서 zip 을 푼 폴더로 들어갑니다
   (안에 「스크립트」 「프롬프트」 「판독대상」 폴더가 보이면 맞습니다)

2. 폴더 안의 빈 곳에서 마우스 오른쪽 버튼을 누릅니다

3. 「터미널에서 열기」 를 고릅니다
   ★ 안 보이면 「추가 옵션 표시」 를 먼저 누르십시오

4. 까만 창이 뜨면 아래를 치고 Enter
      claude          ← Claude Code 를 쓸 때
      codex           ← Codex 를 쓸 때

5. AI 가 뜨면 프롬프트를 통째로 붙여넣습니다
```

**이 방법이면 경로를 타이핑할 일이 없습니다.** 폴더에서 바로 열리기 때문입니다.

#### 방법 ② — 앱에서 폴더 고르기

Claude Code 데스크톱 앱을 쓰신다면, 앱을 열고 **작업할 폴더를 고르는 화면**에서
zip 을 푼 폴더를 지정하시면 됩니다.

---

> **★ 확인하는 법** — AI 에게 이렇게 물어보십시오.
>
> ```
> 지금 어느 폴더에서 일하고 있어?
> ```
>
> 답이 zip 을 푼 그 폴더면 맞습니다.
> 엉뚱한 곳이면 그 창을 닫고 방법 ① 로 다시 하십시오.

> **★ 판독자 ② 도 똑같이** — 다만 **다른 폴더**(`VoC 판독 B`)에서 여십시오.
> 아래 1.1 을 보십시오.

---

### 1.1 어디서 하나

**받으신 zip 을 아무 데나 푸십시오.** 바탕화면이어도 됩니다.
폴더 이름도 상관없습니다. 어디에 풀어도 돌아갑니다.

> ## ★★ 다만 — **판독자마다 폴더를 따로 만드십시오**
>
> ```
> 바탕화면\VoC 판독 A\   ← zip 을 풀고, 판독자 ① 에게 이 폴더를 열어 준다
> 바탕화면\VoC 판독 B\   ← zip 을 또 풀고, 판독자 ② 에게 이 폴더를 열어 준다
> ```
>
> **같은 폴더에서 둘을 돌리면 안 됩니다.**
> 먼저 도는 쪽의 판정 파일이 폴더에 그대로 남아, 뒤에 도는 쪽이 그것을
> 열어 볼 수 있습니다. 그러면 **두 판독이 독립적이지 않게 되어
> 이 방식 전체가 무의미해집니다.**
>
> zip 하나를 두 번 푸시면 됩니다. 데이터도 프롬프트도 똑같습니다.
>
> 다 끝난 뒤 **결과 파일 두 벌을 한 폴더로 모으면** 3차로 넘어갑니다.

### 1.2 무엇이 있어야 하나

**아무것도 준비하실 게 없습니다.** zip 안에 다 들어 있습니다.

```
판독대상\        판독할 데이터        ← 이미 들어 있음
회차배치\        한 번에 볼 행 목록    ← 이미 들어 있음
프롬프트\        붙여넣을 글          ← 이것만 쓰시면 됩니다
판독패키지\      판독자가 읽을 기준서   ← 판독자 LLM 이 알아서 읽습니다
스크립트\        도구                 ← 판독자 LLM 이 알아서 돌립니다
```

> **★ 명령어를 치실 일이 없습니다.**
> 프롬프트 안에 「무엇을 어떻게 돌려라」 가 판독자 LLM 에게 적혀 있습니다.
> 실무자가 하실 일은 **프롬프트를 붙여넣고 기다리는 것**뿐입니다.

> **★ 다른 제품을 판독하실 때는** — 받으신 zip 을 그대로 쓰시고,
> **1차 분석 결과 엑셀만** 판독자에게 주시면 됩니다.
> 「이 엑셀로 준비해 줘」 라고 하시면 판독자가 알아서 앉힙니다.
> zip 을 새로 받으실 필요가 없습니다.
>
> ★ 단, **판독을 이미 시작하신 뒤에는 바꾸지 마십시오.**
> 회차 목록이 바뀌어 앞서 판독한 것과 대조가 안 됩니다.

**혹시 잘 도는지 미리 보고 싶으시면** — 판독자에게 이렇게만 말하십시오.

```
자가점검부터 돌려 줘
```

「준비됐습니다」 가 나오면 그대로 진행하시면 됩니다.
「★ 아직 판독을 시작하면 안 됩니다」 가 나오면 **그 화면을 그대로**
시스템 담당자에게 보내 주십시오. 실무자가 고치실 것이 아닙니다.

### 1.3 어떤 LLM 을 쓰나

**반드시 서로 다른 두 개**를 씁니다. 같은 것을 두 번 돌리면 대조가 안 됩니다.

```
지금까지 쓴 것   Claude Code (Anthropic) · Codex (OpenAI)
```

> **★ 「파일 첨부」 하는 채팅 AI 로는 못 합니다.**
>
> 판독자는 폴더 안의 파일을 **직접 열고, 새 파일을 쓰고, 검사 도구를 돌립니다.**
> 수천 행 CSV 를 여러 회차에 걸쳐 다루므로 첨부로는 되지 않습니다.
>
> ```
> ✅ 됩니다   Claude Code · Codex   — 내 컴퓨터의 폴더를 직접 다루는 도구
> ❌ 안 됩니다 첨부만 되는 채팅창    — 파일을 쓰지도, 도구를 돌리지도 못합니다
> ```
>
> **폴더를 통째로 열어 주는 방식**이면 됩니다.
> zip 을 푼 폴더를 열고, 그 안의 프롬프트를 붙여넣으십시오.

## 2. 돌리기

### 2.1 각각 새 채팅에 붙입니다

```
_판독패키지/0_붙여넣을_프롬프트_도구형.md   ← 파일 내용을 통째로 복사
```

**LLM 두 개에 각각 붙입니다.** 같은 프롬프트, 같은 데이터입니다.

```
★ 반드시 새 채팅이어야 합니다
  앞 대화가 남아 있으면 「전에 이렇게 정했지」 로 기웁니다.
  그러면 두 판독이 독립적이지 않게 되어 대조가 무의미해집니다

★ 서로의 답을 보여 주지 마십시오
  「다른 쪽은 이렇게 했다」 를 알려 주면 그쪽으로 따라갑니다
```

### 2.2 기다립니다

```
한 회차(120행)   30~40분
```

**전체 시간은 데이터 크기에 따라 다릅니다.** 회차 수 × 30~40분입니다.
회차가 몇 개인지는 자가점검이 알려 줍니다.

```
참고 — pilot 1,570행은 14회차 6~8시간
      로니 6,336행은 53회차 30시간 안팎
```

**중간에 끊겨도 괜찮습니다.** 회차마다 파일이 따로 남습니다.

```bash
python run_status.py          # 어디까지 했는지
```

끊긴 지점부터 이어서 하라고 하면 됩니다.

### 2.3 다 됐는지 확인합니다

```bash
python run_status.py
```

```
★ 확인할 것
   판독자별로 **전체 행**이 다 찼는가
   회차별 파일이 **회차 수만큼** 있는가
   ★ 전체 행과 회차 수는 자가점검 화면에 나옵니다

   판독결과_full_01_<이름>.md ~ full_NN_<이름>.md
```

**빠진 회차가 있으면 그 회차만 다시 돌립니다.**
회차 파일 이름을 보고 어느 배치가 비었는지 알 수 있습니다.

## 3. 결과 확인

### 3.1 번들을 만듭니다 — 판독자마다 하나씩

```bash
python build_bundle.py _판독패키지/_결과/판독결과_full_0*_<이름>.md _판독패키지/_결과/판독결과_full_1*_<이름>.md --apply --product all --xlsx --out <이름>_bundle
```

`<이름>` 은 판독자 이름입니다 (`codex` · `claudecode` 등).

### 3.2 자동 검사를 돌립니다

```bash
python check_selfcheck.py _판독패키지/_결과/<이름>_bundle
```

```
★ 읽는 법
   ✗ (실패)   반드시 고쳐야 합니다. 대시보드가 깨지거나 데이터가 틀린 것입니다
   ! (경고)   「사람이 한 번 보라」 는 뜻입니다. 결함이 아닐 수 있습니다
   · (정상)

★ ✗ 가 하나라도 있으면 다음 단계로 넘어가지 마십시오
```

### 3.3 두 판독자를 대조합니다

```bash
★ 3차 입력 만들기는 **총괄**가 합니다 (`3차_준비.py`). 2차 꾸러미에는 그 도구가 없습니다.
```

이게 **3차 감독에게 넘길 입력**을 만듭니다.

```
나오는 것

   s13_judge/ab_mapping.json     ★ 3차에 주지 마십시오
```

```
참고 — pilot 실측
   겹친 1,606행 · 방향 일치 90.0% · 갈린 행 578건 (36%)

## 4. ★ 판독자가 「이건 기준서에 없는데요」 라고 하면

**규칙을 새로 만들어 주지 마십시오. 판독을 멈추지도 마십시오.**

```
❌ 하지 말 것
   실무자가 즉석에서 규칙을 정해 주는 것
   총괄에게 물어보려고 판독을 세우는 것

✅ 할 것
   「판정은 가장 가까운 값으로 하고,
     무엇이 없었는지 기준서개정후보 시트에 적어서 넘기라」 고 하십시오
```

**그 시트가 자동으로 보정요청서에 쌓입니다.**

```bash
python handoff.py
```

```
_인계/보정요청.csv     ★ 이 파일을 시스템 담당자에게 전달합니다
_인계/1차_인계서.md    다음 차수에게 무엇을 넘기는지
```

**규칙 수정은 시스템 담당자가 다음 판에 반영합니다.** 이번 판에서 고치지 않습니다.

## 5. 자주 겪는 일

| 이런 일이 | 이렇게 |
|---|---|
| LLM 이 중간에 멈췄다 | `run_status.py` 로 지점 확인 → 그 회차부터 이어서 |
| 회차 파일이 하나 비었다 | 그 배치 id 파일만 다시 붙여 돌립니다 |
| 검사기가 ✗ 를 냈다 | 메시지에 무엇이 문제인지 적혀 있습니다. 고치고 다시 번들을 만듭니다 |
| LLM 이 새 라벨을 만들었다 | 정상입니다. `python topic_registry.py --register "<판정 파일>"` 을 돌리십시오 |
| 두 판독자가 너무 많이 갈렸다 | 정상 범위는 30~40% 입니다. 60% 를 넘으면 프롬프트가 흔들린 것이니 총괄에게 알리십시오 |
| 「무엇을 채워야 하나요」 라고 묻는다 | 프롬프트에 다 적혀 있습니다. 그대로 다시 읽으라고 하십시오 |
