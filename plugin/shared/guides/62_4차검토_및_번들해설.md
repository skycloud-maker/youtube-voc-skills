**하나만 고르셔야 하는 게 아닙니다.**

```

```

**의견이 있으면 옆에 적으십시오.** 「이건 제외가 맞을 듯」 「분리가 필요해 보임」 같은 것도 좋습니다.


★★ **시트 수를 외우지 마십시오.** 12 → 14 → 15 → 17 로 늘 때마다

## 무엇을 보고 싶을 때 어느 시트를 여나

| 알고 싶은 것 | 볼 시트 |
|---|---|
| **어느 제품의 어느 문제가 급한가** | `improvement_priority` + `개선우선순위_두축.csv` |
| **그 문제의 실제 댓글이 뭔가** | `improvement_evidence_and_ai` |

## 시트별 설명

### ■ raw_voc — 전체 데이터

(행·열 수는 판마다 다릅니다. 지금 값은 첫 장 `0_차례` 에 있습니다.)

모든 행이 여기 있습니다. **행 하나 = 주제 하나**입니다.
댓글 하나에 주제가 둘이면 두 행으로 나뉘어 있습니다.

**꼭 보실 칸**

```
atomic_voc          판정 대상이 된 문장 (댓글에서 잘라낸 대목)
original_voc        원래 댓글 전체
★ topic             무엇에 대한 말인가 — 이게 분류의 핵심입니다
★ topic_group       topic 을 묶은 상위 층 9종
                    성능 · 사용성 · 품질내구 · 가격구매 · 설치배송 ·
                    서비스 · 디자인 · 제품 전반 · 기타
topic_evidence      ★ 그 주제로 본 근거. 원문에서 글자 그대로 뽑은 것입니다
rootcause_problem   ★ 「무엇이 문제인가」 를 한 줄로. 개선 과제로 바로 옮길 수 있습니다
status              normal = 분석 대상 · scope_excluded = 볼 것 없음
scope_exclusion_reason  뺀 이유
product_category    제품군
brand               이 발화가 말하는 제품의 브랜드 (경쟁사면 그 이름)
★ decided_by        누가 정했나
★ decided_note      무엇이 왜 바뀌었나
review_required     Y = 사람이 봐야 함
```

**`decided_by` 읽는 법 — 이 칸이 신뢰도를 말해 줍니다**

```
reader_agree     LLM 둘이 같은 답을 냈다        ★ 총괄 채점 93%
judge_agree      갈려서 감독자가 정했다           ★ 총괄 채점 87% (라벨 기준)
judge_recheck    라벨이 추가된 뒤 다시 판정했다
sky / sky규칙    사람이 정했거나 사람 규칙이 적용됐다
```

### ■ video_summary — 21행 · 영상별 요약

영상마다 댓글 수 · 긍정률 · 부정률 · 문의율과 대표 댓글이 있습니다.
**어느 영상이 반응을 많이 만들었나**를 볼 때 씁니다.

### ■ inquiry_rows — 189행 · 문의만 모은 것

`raw_voc` 와 같은 컬럼인데 **문의로 판정된 행만** 있습니다.
「고객이 무엇을 몰라서 묻는가」 = **안내가 부족한 지점**입니다.

### ■ improvement_priority — 118행 · 개선 우선순위 ★

**제품군 × 주제**로 묶어 점수를 매긴 표입니다. 이 번들의 결론입니다.

```
n              그 묶음의 행 수
neg_count      부정으로 세어진 행 수
neg_ratio      부정 비율
mean_neg       평균 부정 강도
rc_coverage    「무엇이 문제인가」 가 적힌 비율
priority_score = |평균 부정 강도| × 부정 건수
```

**★ 이 한 축만 보면 안 됩니다.**

```
   로봇청소기 내구성/고장   3건 · 평균 -3.67  →  11.0
   세탁기 알림·사운드      86건 · 평균 -0.52  →  11.0
   ★ 같은 점수인데 성격이 정반대입니다
     앞은 「세 명이 크게 화났다」, 뒤는 「여든여섯 명이 조금씩 불편하다」
```

→ **`개선우선순위_두축.csv` 를 같이 보십시오.**

### ■ 개선우선순위_두축.csv — 축이 둘 ★

번들 옆에 따로 있는 파일입니다.

```
건수축_순위     얼마나 많은 사람이 말했나
심각도축_순위   화난 사람은 얼마나 화났나 (건수를 보지 않습니다)
봐야_하는가     어느 축으로든 상위 20 에 들면 표시됩니다

★ 건수가 적다고 아래로 내리지 않습니다.
  1건짜리라도 강도가 높으면 심각도축에서 위로 옵니다
  실측 — 심각도축 상위 14줄이 건수 기준이면 묻혔을 것들이었습니다
```

### ■ improvement_priority_comp — 126행 · 경쟁사 포함본

같은 표인데 **경쟁사 언급 행까지 넣은 것**입니다.
자사만 보려면 `improvement_priority`, 시장 전체를 보려면 이쪽입니다.

### ■ improvement_evidence_and_ai — 279행 · 근거 댓글 ★

우선순위 표의 **각 줄에 실제 댓글**을 붙인 것입니다.
「가격 불만 27건」이 무슨 말인지 보고 싶을 때 엽니다.

```
priority_rank    우선순위 표에서 몇 번째 줄인가
original_voc     실제 댓글
rootcause_problem  ★ 그 댓글에서 읽어낸 문제
```

### ■ 수정로그_오류확정 — 8,461행 · 1차에서 고친 내역

칸 하나가 한 줄입니다. **1차 엔진 값 → 2차 판정 값**이 다 적혀 있습니다.
「왜 값이 바뀌었나」를 따질 때 봅니다. 평소에 볼 시트는 아닙니다.

### ■ 수정로그_재검토필요 — 188행 · ★ 사람이 판정한 기록

**여러분이 직접 정한 행들**입니다. 무엇을 왜 그렇게 정했는지 남아 있습니다.
나중에 「이건 누가 정했지?」 물음이 나오면 여기가 답입니다.

### ■ 분리제안 — 171행 · 나눈 내역

댓글 하나를 여러 주제로 나눈 기록입니다.
`origin_atomic_id` 가 원래 행, `segment_index` 가 몇 번째 조각인지입니다.

### ■ 기준서개정후보 — 20행 · ★ 담을 자리가 없던 것

**LLM 이 「이건 기준서에 담을 라벨이 없다」고 적은 것**입니다.
자동으로 `_인계/보정요청.csv` 에 쌓입니다.

### ■ 구조적결함 — 53행 · ★ 엔진이 잘못 판단한 것

**1차 엔진 로직의 문제**를 원인 단위로 적은 것입니다. 행 단위가 아닙니다.
이것도 보정요청서로 갑니다.

### ■ 판정불일치 — 0행

행 판정과 칸 판정이 어긋난 경우입니다. **0이어야 정상입니다.**

## 3. 자주 하는 질문

**Q. 「제외」된 댓글은 버려진 건가요?**
아닙니다. `raw_voc` 에 그대로 있고 `status=scope_excluded` 로 표시돼 있을 뿐입니다.
`scope_exclusion_reason` 에 왜 뺐는지 적혀 있습니다.

**Q. 라벨이 69.8% 인데 나머지는요?**
30.2% 는 제외입니다 — 채널 칭찬 · 인사 · 잡담 · 광고 · 영상 대본입니다.
**「미분류」는 0입니다.** 모든 행이 라벨이 붙었거나 뺀 이유가 적혀 있습니다.

**Q. 이 숫자를 믿어도 되나요?**
구간마다 다릅니다. `decided_by` 를 보십시오.
자세한 것은 재현설계서 **§9 「어디까지 믿어도 되는가」** 에 있습니다.

**Q. 새 영상이 나오면 어떻게 하나요?**
`60_2차판독_실무자_사용가이드.md` 부터 다시 시작하시면 됩니다.
