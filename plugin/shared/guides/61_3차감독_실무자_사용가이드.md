> **걸리는 시간** — 준비 5분 · LLM 작업 40분~1시간 × 2 · 확인 10분
> **앞 단계** — `60_2차판독_실무자_사용가이드.md`

## ★ 2026-08-23 부터 달라진 것 — 여기부터 읽으십시오

아래 「1. 준비」 이후는 예전 방식입니다. **지금은 이렇게 합니다.**

### 폴더는 총괄이 차려 줍니다

총괄이 2차 결과를 점검하고, **갈린 행만 익명화해서** 넣은 폴더 둘을 줍니다.

```
3차 감독1\      ← 그대로 받습니다
3차 감독2\      ← 그대로 받습니다
```

★ **2차 결과 폴더를 옮길 일이 없습니다.** 감독 폴더 안에
  `s13_judge\judge_input.csv` 가 이미 들어 있습니다.

★ 왜 총괄이 만드나 — 감독자가 만들면 **2차 판독 결과를 봐야 하고,**
  그러면 A 와 B 가 누구인지 알게 됩니다. 알면 편들게 됩니다.
  총괄이 만들면 감독자에게는 알 방법이 아예 없습니다 —
  2차 번들도, 매핑도, 만드는 코드도 없습니다.

### 하는 일은 셋뿐입니다

```
① 총괄이 차려 준 폴더 둘에서 각각 AI 를 열어 프롬프트를 붙여넣고
② 「judge_NN 까지 했습니다」 하고 멈추면 **같은 프롬프트를 다시** 붙여넣기
③ 다 끝나면 **두 폴더를 그대로** 총괄께 넘기기
```

★ 3차는 **이어가기 프롬프트가 따로 없습니다.** 처음 것을 그대로 다시 쓰면
  판독자가 「없는 회차부터」 이어서 합니다. 12회차라 보통 한두 번입니다.

### 판독자가 스스로 하는 것 (사람이 시키지 않습니다)

```
자가점검.py        시작할 수 있는 자리인가
성실성검사.py       얕게 하지 않았나 · 적힌 시각이 누적인가
지문검사.py        도구·기준을 고쳤나
넘어가도_되나.py    다음으로 넘어가도 되는지 스스로 판단
```

## ★★ 통합은 총괄이 합니다 — 감독자는 판정까지 (sky 2026-08-24)

감독자는 **자기 폴더에서 판정만** 합니다. 다른 감독자 결과를 찾지도, 가져오지도
않습니다. **감독 폴더는 한 사람 것만 있어야 합니다.**

```
① 감독자1 폴더 · 감독자2 폴더에서 각각 판정을 마친다
② 두 폴더를 **그대로** 총괄에게 넘긴다
③ 총괄이 자기 자리에서 합치고 꾸민다
```

★ 왜 이렇게 하나 — 자동으로 합치게 했더니 **감독자 결과가 폴더끼리 복사**됐고,
  그러면 「본인 폴더가 아닌데 상대편 결과물이」 들어가는 일이 생깁니다.
  누가 무엇을 했는지 알 수 없게 됩니다.

★ 총괄이 하는 것 (실무자가 신경 쓸 일 아닙니다)

```
3차_준비.py          2차 점검 → 갈린 행 익명화 → 감독 폴더 둘을 차림
3차_마무리.py        두 폴더를 받아 통합 → 검사 → 보정요청 → 논의본
번들_마무리꾸미기.py   시트 차례 · 묶음 색 · 데이터 안내
```

### 끝나면 받는 것 — `_최종결과\`

```
★ 3차_최종데이터.xlsx      이것 하나면 됩니다 (첫 장이 차례입니다)
★ 보정요청_논의본.md        회의에는 이쪽이 낫습니다
  사람이볼목록.csv          감독자끼리 갈려 사람이 정할 행
  보정요청.csv
  참조용_개별결과\          2차 A·B · 3차 감독 둘의 원본
```

### xlsx 안에 무엇이 있나

★★ **시트 수를 외우지 마십시오.** 판마다 늡니다.
  **첫 장 `0_차례`** 를 여십시오 — 어느 시트를, 누가, 왜 보는지,
  몇 행인지가 거기 적혀 있습니다. 순서도 앞에서부터 볼 것 순입니다.

```
0_차례          여기부터 — 나머지를 안내합니다
raw_voc         판정 결과 전부 · 대시보드가 읽는 장
★PL Issue       안전·위생 전량
★사람이볼목록     감독자 둘이 갈려 사람이 정할 행
★보정요청        2차·3차에서 쌓인 보정 요청 전부
그 뒤            1차 엔진이 낸 집계 · 2차 판독 로그 · 검사 결과
```

★ `기준서개정후보` · `구조적결함` · `판정불일치` 가 비어 있어도
  **틀린 것이 아닙니다.**
  앞의 둘은 2차 판독자가 번들에 남긴 것만 담고, 3차 것은 `★보정요청` 에 있습니다.
  `판정불일치` 는 형식 검사라 0 이면 어긋난 행이 없다는 뜻입니다.

## 1. 준비 — ★ 총괄이 차려 줍니다

총괄이 2차 결과를 점검하고, **갈린 행만 익명화해서** 넣은 폴더 둘을 줍니다.

```
3차 감독1\      ← 그대로 받습니다
3차 감독2\      ← 그대로 받습니다
```

폴더 안에 이미 들어 있습니다.

```
s13_judge\judge_input.csv       감독할 것 (2차에서 갈린 행만)
s13_judge\judge_NN_ids.txt      회차 나누기
   ★ 몇 회차인지는 그 폴더를 세어 보면 됩니다
```

**없으면 총괄에게 요청하십시오.** 스스로 만들려 하지 마십시오.

### ★ 왜 총괄이 만드나

```
만들려면 2차 판독 결과를 봐야 합니다.
그것을 보면 **A 와 B 가 누구인지 알게 됩니다.** 알면 편듭니다.

★ 그래서 감독 폴더에는 아예 없습니다
     2차 번들 없음 · ab_mapping.json 없음
     만드는 코드(make_judge_input.py) 없음

  ★ 정답지 파일을 안 줘도 **만드는 코드**를 주면 소용이 없습니다 —
    고정 씨앗을 쓰므로 돌리면 매핑이 그대로 재현됩니다
    「정답지는 채점용이지 판독자에게 주는 대조표가 아니다」 (sky)

★ 실측 — 안 보여 줬더니 감독자가 자기 답을 39% 만 골랐습니다.
  편들지 않았다는 증거이고, 이 방식이 작동한다는 증거입니다
```

## 2. 돌리기

### 2.1 각각 새 채팅에 붙입니다

```
_판독패키지/0_붙여넣을_프롬프트_감독.md   ← 파일 내용을 통째로 복사
```

**LLM 두 개에 각각 붙입니다.**

```
★ 2차를 돌린 그 세션에 붙이지 마십시오
  두 답 중 하나를 자기가 쓴 것이라, 이미 결론을 내린 상태입니다.
  자기 답을 뒤집으라고 하는 셈이라 편들 수밖에 없습니다

★ 새 채팅이면 어느 회사 LLM 이든 상관없습니다.
  A·B 로 가려 놓았으니 자기 것을 알 수 없습니다
```

### 2.2 감독자가 하는 일

행마다 셋 중 하나입니다.

```
A   A 가 맞다
B   B 가 맞다
C   ★ 둘 다 아니다 — 감독자가 직접 답을 내고 이유 한 줄
D   ★★ 둘 다 맞다 — 한 행에 주제가 여럿이라 나눠야 한다
```

★ `D` 는 2026-08-25 에 새로 넣었습니다.

> 「A,B를 단순히 일치/불일치/둘다아니면뭐? 3가지만 판단해서 넣는 것이
>   아니라는 얘기입니다 … 2차 후에도 과소분리된 것은 없는지,
>   판독은 제대로 된건지를 검토하는 역할이 되고 그게 바로 감독」 (sky)

왜 넣었나 — 4차에서 사람이볼목록 69행 중 **11행이 「둘 다 맞다, 나눠야 한다」**
였습니다. 감독이 말할 칸이 없어서 억지로 하나를 골랐고, 갈렸고, 사람에게
넘어왔습니다. **말할 칸이 없어서 사람 일감이 된 것입니다.**

★ 감독이 받는 것도 늘렸습니다.

```
예전   atomic_id · product · voc_cleaned · atomic_voc · A · B
지금   + original_voc      원문 전체 (atomic 은 그 조각이다)
       + parent_voc        답글이면 부모 댓글
       + video_title       어느 영상인가
       + 이_원문의_조각수   과소·과분리를 보는 자리
```

**「모르겠다」로 넘기지 못하게 되어 있습니다.** 갈린 행 **전부**에 답을 냅니다.
(행 수는 `judge_input.csv` 를 세어 보면 됩니다. pilot 에서는 578행이었습니다.)

### 2.3 기다립니다

```
한 회차(약 145행)   15~20분
전체 4회차          40분~1시간
```

```
3차 감독2\_판독패키지\_결과\감독결과_*.md
```

★★ **감독자는 판정까지입니다.** (sky 2026-08-24)

```
❌ 두 감독자를 합치지 않는다
```

★ 왜 — 예전에는 감독자가 스스로 합치게 했습니다. 그러다 **한쪽 폴더에
  상대편 결과물이 들어가** 있었고, 「가장 새 번들」 규칙이 남의 것을 골라
  **보정요청 3건이 사라졌습니다.** 감독 폴더는 한 사람 것만 있어야 합니다.

### 넘어가도 되는지는 감독자가 스스로 봅니다

```bash
python 넘어가도_되나.py
```

```
★ 확인할 것
   판정이 회차 수만큼 있는가
   judge_input.csv 의 **모든 행**에 답이 있는가
```

### 그 다음은 총괄이 합니다

```
python 3차_마무리.py        통합 → 자가검사 → 보정요청 → 편향검사 → 논의본

```

실무자가 하실 일은 **두 폴더를 그대로 넘기는 것**뿐입니다.

```

   실전    1,701행 → 판독자 합의 4,791 · 감독자 합의 1,632 · ★감독자 갈림 69
```

### 어느 판독자가 더 많이 채택됐는지

없으므로 **감독자 쪽에서는 알 수 없습니다** — 그게 맞습니다.

```

   실전    claudecode 57.3% · codex 51.5%  → 치우침 없음
```

## 4. ★ 감독자가 「확인 요청」 을 올리면

감독자는 **자기가 못 정하는 것이 아니라, 회사가 정해야 하는 것**만 올리게 되어 있습니다.

```
예)  「스타일러가 대상 제품군인가 (8행)」
     「리뷰어가 고정 댓글에 쓴 제품 평가를 VoC 로 볼 것인가 (6행)」
```

```
★ 행 단위가 아니라 묶음으로 올라옵니다
★ 상한이 걸려 있습니다 — 묶음 10개 · 대상의 20% 이내
   넘으면 감독자가 스스로 판정하거나 묶음을 합쳐야 합니다
```

**이건 실무자가 판단하실 것입니다.** 한 묶음에 한 번만 답하면 됩니다.
그 답이 다음 판에 규칙으로 들어가 같은 것이 다시 안 올라옵니다.

**규칙 자체를 고치는 일이면** 답만 주고, 반영은 시스템 담당자에게 넘기십시오.

**보정요청서를 뽑는 것도 총괄이 합니다.** 감독자는 확인요청만 올리면 됩니다.

## 5. 자주 겪는 일

| 이런 일이 | 이렇게 |
|---|---|
| 감독자가 A/B 가 누구냐고 묻는다 | 「알 필요 없습니다」 라고 하십시오. 알면 편듭니다 |
| 감독자 둘이 너무 많이 갈렸다 | 정상 범위는 25~30% 입니다. 넘으면 라벨이 모자란 것일 수 있습니다 (아래) |
| 「담을 라벨이 없다」 는 말이 반복된다 | ★ 중요한 신호입니다. 택소노미에 구멍이 있다는 뜻이니 보정요청에 담기게 하십시오 |
| C(제3의 답)가 너무 많다 | 두 판독자가 다 헛짚었다는 뜻입니다. 2차 프롬프트를 점검해야 합니다 |
| 새 라벨을 만들었다 | `python topic_registry.py --register "<감독자 파일>"` |

### ★ 「담을 라벨이 없다」 가 왜 중요한가

pilot 에서 감독자까지 거치고도 갈린 159건을 총괄이 채점했더니,
**틀린 것 중 절반이 「담을 라벨이 그때 없어서」** 였습니다.

```
총괄이 적은 대안이 한 곳으로 몰렸습니다
   「청소/관리」 13회 · 「세탁·건조 시간」 4 · 「옷감 꼬임」 3 · 「공간 활용성」 2

→ topic 6종을 신설했습니다 (48종 → 67종)

★ LLM 이 갈리는 자리를 보면 분류 체계의 구멍이 보입니다.
  이게 이 단계의 부수 소득입니다
```
