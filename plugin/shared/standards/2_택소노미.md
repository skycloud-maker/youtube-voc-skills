# VoC Topic 택소노미 재설계 v0.10 — 잠정 서술·제품군별 기타·위생/살균 개명

> **상태: v0.9 판정 절차 계승 + R-C3-16 잠정 서술 및 제품군별 기타 라벨 반영**
> v0.9 대비 변경: **topic_provisional 자유 서술 복원** · **제품군별 기타 4개 신설** · **`위생/살균(물상태)`을 `위생/살균`으로 개명**
> topic에서 제품·감성을 빼고 '이유'만 남긴다. (원칙 불변)
>
> **v0.7 신설 목적** — 파일럿 QA Round 1에서 "그 라벨의 어휘가 원문에 전혀 없는데 배정된" 오류가 12건 이상 확인됨
> (예: "스테이션 비주얼 미쳤네요" → `내구성/고장`, "충전브라켓 고정이 잘 되나요" → `A/S·고객응대`).
> 9차 QA에서 `가격/가성비` 한 라벨에만 적용했던 **"어휘 존재 여부로 판정"** 원칙을 **전 라벨로 일반화**하기 위해,
> 라벨별 판정 근거 어휘를 이 문서에서 정본으로 관리한다. 엔진의 E1 가드는 이 목록을 입력으로 사용한다.

## 2. product_category — 원문 우선 판단 (v0.7 강화)

- 값: 로봇청소기 · 식기세척기 · 세탁기 · 건조기 · 냉장고 · 기타
- **판단 순서**: ①원문 → ②parent 댓글 → ③영상(title/tags/desc)
- **①원문 우선**: 모델명(로니·로보락·드리미…) + 제품군 고유 기능어(스테이션·더스트백·히든·직배수·물걸레받이·걸레질·문턱/매트 등반·먼지통·회피력·쇼파 아래 청소 등)가 원문에 있으면 원문에서 확정
- 원문에 단서가 없으면 parent/영상 참조. 그래도 불명확하면 **기타**
- **과발화 금지**: 제품군 신호 없이 일반어(가격·비교·bare 스팀)면 기타 유지

**⚠ v0.7 신설 — 실행 힌트 금지 조항**

> `keyword`(검색 키워드)와 `product`(제품 힌트)는 **수집 파라미터이지 판단 근거가 아니다.**
> 이 값들을 product_category 판단에 사용해서는 안 되며, `product_category_source`에는
> `text` / `parent` / `video` **셋 중 하나만** 기록한다. 힌트로 확정한 값을 `text`로 기록하는 것은 오류다.

*(배경: 파일럿에서 458행 전부 `keyword=로봇청소기 | product=로봇청소기`가 컨텍스트에 주입되어,
"미니 김치냉장고도 리뷰해주세요" 같은 발화까지 `product_category=로봇청소기 / source=text`로 기록됨)*

## 3. 이유(reason) 어휘 — 제품군별 + 공통 (v0.6 계승)

**공통 (모든 제품군)**
제품 전반 · 제조사 신뢰/품질(원산지·국산여부·ODM/JDM) · 내구성/고장 · 에러/오작동 · **안전(화재·감전·누수)** · A/S·고객응대 · 가격/가성비 · **구매의사** · 프로모션 · 소모품/유지관리재 · 설치/설치 편의성 · 배송 · 구독 · 소음/진동 · 디자인 · 사용 편의성(조작) · **앱/스마트(원격제어)** · 용량

**로봇청소기 전용** (raw50·귀곰 후기 ✓)
동선/주행 ✓ · 주행/문턱돌파 ✓ · 청소/흡입 성능 ✓ · 장애물 회피 ✓ · 물걸레 ✓ · 스팀 ✓ · 배터리 ✓ · 먼지통/자동비움 ✓

**식기세척기 전용** (165 ✓)
세척 성능 · 건조 성능 · 식기 수납 · 위생/살균 · 노즐/잔수 · 누수/도어 · 배수·부품

**세탁기·건조기** 세탁 성능 · 탈수 · 스팀 · 의류 냄새 · 옷감 손상 (확장 어휘는 어휘팩 v0.2 준용)
**냉장고** 냉각 · 신선보관 · 제빙/정수 · 성에 · 수납(선반·도어)

**제품군별 기타** 기타(로봇청소기) · 기타(식기세척기) · 기타(세탁기) · 기타(냉장고)

- `기타(제품명)`은 제품군은 확정되었지만 모든 기존 캐노니컬 라벨을 검토해도 맞는 이유 라벨이 없을 때만 사용한다.
- 제품군 자체를 특정하지 못한 경우에는 `기타(제품명)`이 아니라 `미분류`를 사용한다.
- `기타(공통)`은 만들지 않는다. 공통적인 전반 평가에는 기존 `제품 전반`을 사용한다.
- `topic_provisional`에는 기타를 고른 이유와 기존 라벨로 설명할 수 없는 내용을 자유 서술로 남긴다.

> **'제품 비교'**(로보락 vs LG 등)는 topic이 아니라 inquiry/need 레이어.

## 4. include / exclude (핵심 라벨 · v0.6 계승)

- **동선/주행**(로청) — include: 경로·못 가는 구역·쇼파 아래·갇힘·알고리즘·인식/회피 실패 / exclude: 문턱·매트 등반은 `주행/문턱돌파`, 고장은 `내구성/고장`, 조작 UI는 `사용 편의성`
- **주행/문턱돌파**(로청) — include: 문턱·단차·경사·매트·층간소음매트 등반/주파 성공·실패, 돌파 높이(cm) / exclude: 실내 경로·구역은 `동선/주행`
- **청소/흡입 성능**(로청) — include: 먼지·머리카락·흡입력·청소 결과 / exclude: 경로는 `동선/주행`
- **앱/스마트(원격제어)** — include: 소프트웨어·앱·지도/맵핑·지도 저장·원격제어·펌웨어 / exclude: 물리적 경로는 `동선/주행`
- **소모품/유지관리재** — include: 먼지봉투·필터·물걸레패드·세제·린스·소금 등 / exclude: 투입 편의는 `사용 편의성`, 세척 결과는 성능 라벨
- **제품 전반** — include: 구체 대상 없는 전반 만족/불만 / exclude: 구체 요소는 세부 라벨 우선
- **제조사 신뢰/품질** — include: 브랜드·제조사·원산지 신뢰/품질 / exclude: 구체 고장은 `내구성/고장`, AS는 `A/S·고객응대`
- **구매의사** — include: 구매·재구매를 하지 않겠다는 의사 표명
  > ★ **2차 해석 확장** 【CP-36 · sky 결정 2026-08-16】 — 긍정 의사도 포함한다.
  > "무조건 삽니다" · "오.. 너로 정했다" · "오늘 결제하고 오는 길".
  > 이름은 「구매의사」 인데 정의가 이탈만 덮고 있어 긍정에 갈 곳이 없었다.
  > §8 표의 "무조건 삽니다 → N/A" 는 이 결정으로 대체된다.
  > ★ 1차 산출물은 소급 변경하지 않는다. 2차 판독에만 적용한다. 정본은 부록 §3-7 / exclude: 가격 자체 평가는 `가격/가성비`, 브랜드·품질 평가는 `제조사 신뢰/품질`, CEJ 단계명 자체는 근거가 아님

## 5. topic 배정 원칙 (규율 v2 §4 계승)

- **`가격/가성비`는 원문에 가격·비용·금액 어휘가 실제 존재할 때만 배정.** 단순 브랜드 비교, 구매 고민만으로는 배정하지 않는다.
- **설치 공간/환경 제약**은 `설치/설치 편의성`으로 우선 배정.
- **맥락상 무관한 리액션/농담**은 억지 배정하지 말고 `미분류`(또는 scope_excluded).
- topic에 해석 태그 부착 금지(R4) · 명명 가능하면 N/A 금지(R5) · 카테고리 수준 유지(R2).
- **일반화 교훈**: 오분류를 고칠 때 "그 문장"만 고치지 말고 판정 기준 자체(어휘 존재 여부, 최소 근거 길이)를 일반화한다.

## 6. 【v0.7 신설】 라벨별 판정 근거 어휘 목록

**용도** — 엔진 E1 가드의 입력 사양. topic을 배정하기 전에 **해당 라벨의 근거 어휘가 atomic 안에 실제로 존재하는지** 확인한다.

**사용 규칙**
1. 아래 어휘는 **정확 일치가 아니라 의미 일치**로 판단한다(활용형·구어·오타 포함). 예: "고장나", "고장났", "맛이 갔" 모두 `내구성/고장` 어휘로 인정.
2. 어휘가 **하나도 발견되지 않으면 그 라벨은 배정할 수 없다.** `미분류`로 내리고 사유를 `topic_evidence`에 남긴다.
3. 두 라벨의 어휘가 동시에 발견되면 §4 include/exclude로 판정하고, 그래도 나뉘면 **atomic 분리 후보**로 본다(E2).
4. 이 목록은 **닫힌 목록이 아니다.** 신규 어휘가 반복 등장하면 이 문서를 개정해 추가한다(`inquiry_type_raw`/`need_signal_type_raw` 축적분을 정기 검토).
5. **`기타(제품명)` 4개는 E1 근거 어휘 검사를 적용하지 않는다.** 어휘가 없는 새 이유를 수집하기 위한 라벨이므로, E1을 적용하면 모두 `미분류`로 되돌아간다. 대신 제품군 불일치는 값을 덮어쓰지 않고 `review_required=Y`와 trace로 표시한다.

## 7. 【v0.7 신설】 topic 판정 절차 (E1)

```
STEP A. atomic_voc 를 읽는다.
STEP B. §6에서 근거 어휘가 발견되는 라벨을 모두 수집한다.
STEP C. 수집 결과에 따라 분기
   0개  → 제품군이 확정되고 기존 라벨로 설명할 수 없는 새 이유이면 기타(제품명)
          제품군 미특정 또는 새 이유가 아니면 미분류 (또는 §8에 따라 N/A / scope_excluded)
   1개  → 그 라벨로 확정
   2개+ → §4 include/exclude 로 판정
          · 상하위 관계면 하위(구체) 라벨 우선   예: 제품 전반 < 물걸레
          · 서로 독립이면 → E2 분리 후보로 반환 (atomic을 다시 쪼갠다)
STEP D. topic_evidence 에 판정 근거 어휘와 판단 차수를 남긴다.
```

**금지 사항**
- 근거 어휘 없이 "문맥상 그럴 것 같아서" 배정하는 것 — **가장 흔한 오류 유형**
- 구체 라벨 어휘가 있는데 `제품 전반`으로 뭉개는 것
- 제품군명(로봇청소기 등)·감성어(불만족 등)·CEJ 단계명을 topic에 넣는 것

**실제 오류 사례 (파일럿 Round 1)**

| atomic | 배정됐던 topic | 근거 어휘 존재 여부 | 정정 |
|---|---|---|---|
| "스테이션 비주얼 미쳤네요 인테리어 효과 너무 부러워요" | 내구성/고장 | 고장·파손·수명 어휘 **0** | → 디자인 |
| "머리카락 엉킴이나 충전브라켓의 고정이 잘 되나요" | A/S·고객응대 | AS·센터·수리 어휘 **0** | → 미분류 또는 청소/흡입 성능 |
| "매트 깔려있으면 스팀이랑 물걸레가 안 된다고" | A/S·고객응대 | 동일 **0** | → 물걸레 / 스팀 |
| "캡슐세제가 개구리세제보다 세척력이…" | 앱/스마트(원격제어) | 앱·지도·원격 어휘 **0** | → scope_excluded (범위밖) |

## 8. 【v0.7 신설】 미분류 · N/A · scope_excluded 판정

topic 자리에 들어갈 수 있는 특수값과 그 앞단의 제외 판정을 하나의 순서로 정리한다.

```
① 제품에 대한 실질 내용이 있는가? (§6 근거 어휘 ≥ 1)
      Yes → topic = 해당 캐노니컬 라벨
      No  → ②

② 근거 어휘는 없지만 제품 관련 실질 VoC이긴 한가?
      Yes → topic = "미분류"        (택소노미 확장 후보로 별도 검토)
      No  → ③

③ 라벨도 없고 실질 내용도 없지만, 니즈 신호 또는 감성 신호가 있는가?
      Yes → topic = "N/A"           (모수 포함, topic 집계에서만 제외)
      No  → ④

④ scope_excluded + scope_exclusion_reason
```

| 값 | 정의 | 예 |
|---|---|---|
| **캐노니컬 라벨** | §6 근거 어휘가 존재 | "문턱은 잘 넘나요?" → 주행/문턱돌파 |
| **미분류** | 실질 제품 VoC이나 캐노니컬 라벨 없음 | "택갈이 제품은 별루" |
| **N/A** | 라벨 없음 + 실질 내용 없음 + **니즈·감성 신호는 있음** | "무조건 삽니다"(conversion_signal) |
| **scope_excluded** | 위 어디에도 해당 없음 | "미니 김치냉장고도 리뷰해주세요"(channel_request) |

`기타(제품명)`은 캐노니컬 라벨이지만 미판정률을 계산할 때는 `미분류`·`N/A`와 함께 별도 집계한다. 새 라벨 후보를 축적하기 위한 관찰값이지 기존 라벨 판정을 완료했다는 뜻이 아니다.

- **빈칸은 허용하지 않는다.** N/A는 반드시 문자열 `"N/A"`로 기록한다.
- `scope_exclusion_reason` 7종: empty / operator_notice / channel_request / channel_feedback / out_of_scope_product / no_analytic_value / unresolvable_reply

## 9. 검증 근거 (v0.6 계승)

- 식기세척기 150: 제품군 불일치 9.7% → 0%, 유효 55% → 64%
- 로청 재검증 43: 로청·공통 라벨 균형 발화, 앱/스마트까지
- held-out 19(튜닝 미사용): topic 일반화 확인 · product_category 원문우선 강화 후 로봇청소기 11→15, 과발화·회귀 없음
- **파일럿 QA Round 1 (2026-08-06, 458행)**: 택소노미 밖 값 **0건**(라벨 체계 자체는 건전). 다만 근거 어휘 없는 배정이 12건 이상 → **§6·§7 신설의 직접 근거**
- **사이클2-B T3 어휘 검증 (2026-08-11)**: 지시서 기준 어휘 부재 176건 중 15건 해소(세탁 성능 5 · 사용 편의성 5 · 내구성/고장 5), 정상행 전수 변화 후보 원문 대조 결과 오탐 0건. R-C2-08 정정으로 T1에서 T3로 이동한 `atomic_extract_guard` 4건은 본 모수에서 분리했다.
- **보류 판단**: `통돌이`·`드럼`은 세탁 방식/제품형태 명사라 단독 topic 근거로 쓰지 않는다. 단독 추가 dry-run에서 각각 정상행 topic 변화 후보 86건·55건이 발생했다. `중국`·`기술`도 구매 비교와 일반 맥락 과발화 위험 때문에 제조사 신뢰/품질에 추가하지 않았다.
- **v0.9 일반성 검증 (2026-08-12, 1,744행)**: 오탐 0건, 같은 스코프의 서로 다른 source 2건 이상 반복, 그리고 **그 표현이 해당 라벨을 특정함**을 모두 요구한다. 여러 라벨에 붙을 수 있는 감정 강도·비교 우위·일반 칭찬은 topic 어휘로 쓰지 않는다. `한국인인 것이 넘 자랑스럽`, `1도안귀찮`, `시간확인`, `다시 장착`, `망을 비우`, `잘닦`, `고정이 안`, `애벌 설겆이` 등 표본 전용 14개는 폐기했다. `비교도 안되게 좋`/`비교가 안되게 좋`은 통합 후 반복성 기준을 통과했지만 topic 근거가 아닌 감정 강도 표현이고 라벨 고정이 불가능해 미채택했다. `비쌉니다` 등 재시도 후보 4개도 이번 버전에는 넣지 않았다. `소재/마감 품질`은 기존 라벨과의 경계 및 오탐 기준을 충족하지 못해 미채택했다.
- **R-C3-13 등록**: v0.8 운영 어휘 310개 중 0회 매칭 113개, 1회 매칭 59개로 저빈도 어휘가 172개(55%)였다. 표본 규모 한계가 있어 이번 버전에서 삭제·정리하지 않고 별도 조사 안건으로 남긴다.
