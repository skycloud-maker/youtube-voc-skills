# A. 보지 않는다 — 원천 고정값 (12칸)

**YouTube API 또는 수집 단계에서 확정된 값이다. 판정 대상이 아니다.**
값이 이상해 보여도 2차가 고칠 수 있는 것이 아니다. 수집 단계 문제로 별도 보고한다.

| 컬럼 | 근거 |
|---|---|
| `source_id` · `raw_row_index` | 식별자 |
| `parent_voc_id` · `comment_relation` | 댓글 구조 (API) |
| `original_voc` | 원문 그대로 (API) |
| `video_id` · `video_title` · `video_url` | 영상 메타 (API) |
| `reference_brand` | 수집 조건 (자사 관점 고정값) |

> ★ `video_title` 은 **판정의 근거로는 쓰되 판정 대상은 아니다.**
> 그리고 R18·§7.6 — 영상 메타만 근거로 `entity_role` 을 바꾸지 않는다.
>
> ★ `video_tags` · `video_description` 은 66컬럼에 없다. 1차가 LLM 입력으로만
> 쓰고 출력에서 뺐다 (D-30). 판독자는 이 두 값을 볼 수 없다.

# B. 보지 않는다 — 기계가 계산한 값 (11칸)

**결정론적 후처리다. LLM 출력을 쓰지 않는다.** 값을 제안하지 말 것.
다만 **계산식과 어긋나면** 그것은 보고 대상이다 (값이 아니라 정합성을 본다).

| 컬럼 | 규칙 |
|---|---|
| `confidence_rating` | 정본 §7.10 — Topic·TEE·RootCause 조합으로 엔진이 계산 |
| `voc_total_score` | 축 점수 합산 |
| `atomic_id` · `atomic_index` | 분리 결과로 부여 |
| `proposal_flag` | 처리 경로 표시 |
| **`product_category` · `product_category_source`** | **【v1.1 이동】 코드 `ENGINE_OWNED_COLUMNS`. 값을 제안하지 않는다** |

> ★ Claude Code 도구형이 `confidence_rating` 을 「기준서 미커버」로 낸 적이 있다.
> "Topic 없음" 의 정의(미분류·N/A 를 Topic 있음으로 셀지)가 미정이라는 지적이며,
> 그것은 **기준서 개정 후보로는 타당하다.** 값을 제안하는 것과 구분한다.

# D. ★ 판정 대상 — LLM 판단값 (32칸)

**여기가 2차의 일이다.** 아래 표의 [축] 은 도구형 프롬프트 축 점검표와 대응한다.

> **★ 【v1.2 정정】 "D 32칸 = LLM_JUDGED" 가 아니다** — Claude Code 도구형 지적
>
> 코드는 컬럼을 셋으로 나눈다. D 는 그중 **둘**에 걸쳐 있다.
> ```
> LLM_JUDGED_COLUMNS   topic · cej · entity_role · 점수류 · confidence 6종 ...
> FREE_TEXT_COLUMNS    atomic_voc_summary · topic_provisional ·
>                      topic_evidence · cej_evidence · tee_*_evidence ·
>                      tee_summary · rootcause_summary · *_raw · trace_summary
> ENGINE_OWNED_COLUMNS 판정 대상이 아니다 (B 로 감)
> ```
> **D 의 기준은 "코드가 어느 그룹에 넣었나" 가 아니라 "2차가 값을 채우는가" 다.**
> `atomic_voc_summary` 와 evidence 류는 FREE_TEXT 이지만 2차가 채운다.
> `trace_summary` 는 FREE_TEXT 이면서 2차가 채우지 않는다 (C 참고).
> 두 축을 혼동하지 않는다.

| 축 | 컬럼 | 핵심 규칙 |
|---|---|---|

# 판정 대상이 아닌데 판정하면 생기는 일

```
2026-08-14 배치01 실측 — 네 판독자 100행

  status 축      75건    ← 배치가 그쪽 후보였고, 판정하기 쉬운 축이다
  TEE 근거        0건    ← 전역 1,050행(66.9%)이 걸린 축인데 아무도 안 봤다
  분리            2건    ← 전역 129행
```

**판정 대상이 넓게 열려 있으면 판독자는 가장 쉬운 축으로 쏠린다.**
그래서 축 점검표(10축)와 이 분류표(A/B/C/D)를 함께 준다.

# 실측 변동성 — 참고

형제 atomic 이 있는 source 22개로 검사했다.

```
전 행 상수 4       reference_brand · market · split_origin_atomic_id · secondary_topic_source
source 단위 21     형제끼리 항상 같음. status · scope_exclusion_reason · 영상 메타 · 정제문 등
atomic 단위 46     형제끼리 달라짐. topic · cej · tee · rootcause · entity_role 등
```

> ★ **`status` 와 `scope_exclusion_reason` 이 source 단위다.** 이것이 D-31 의 구조다.
> atomic 이 개별적으로 `scope_excluded` 로 판정돼도 source 값에 눌린다 (381행).
> 2차가 `status` 를 제안할 때는 **형제 전체에 걸린다**는 점을 알고 제안해야 한다.
>
> ★ `inquiry_flag` 도 source 단위인데 `inquiry_type` 은 atomic 단위다.
> 한 형제가 질문이면 모든 형제의 flag 가 Y 가 된다. 정합성 점검 시 유의한다.

# ★ 코드끼리도 어긋난 곳 — review_required   【v1.3 · 2026-08-15】

25번은 "문서와 코드가 다르면 코드를 따른다" 고 정했다.
그런데 이 칸은 **코드끼리 어긋나 있다.**

```
schema.py       LLM_JUDGED_COLUMNS 에 들어 있다
engine.py       ★ 코드가 직접 값을 대입한다
                row["review_required"] = "Y" / "N"
                candidate["review_required"] = "Y"
                normalized_row["review_required"] = "Y"
부록 §4.3       기계 계산
build_bundle    compute_derived() 가 분리 생성 행에 'Y' 를 강제한다

결론   실제 동작이 정본이다 — 기계 계산이다. 부록이 옳았다
       schema.py 의 분류가 동작과 다르다. 판독자는 이 칸을 채우지 않는다
```

**규칙을 한 줄 보탠다**

```
문서 vs 코드      코드를 따른다 (기존)
★ 코드 vs 코드    「값을 실제로 쓰는 코드」 를 따른다
                 선언(schema.py 의 분류)보다 동작(engine.py 의 대입)이 우선이다
                 그리고 어긋났다는 사실을 보고한다
```

# 변경 이력 · v1.1 정정 (2026-08-15 · CP-22)

**세 곳이 틀렸다. 코드 `schema.py` 의 소유권 그룹이 정본이다.**

```
                          v1.0 (틀림)      코드 정본
product_category           D 판정 대상      ENGINE_OWNED      → B 로 이동
product_category_source    B               ENGINE_OWNED      → 유지 (분류만 명시)
brand · market · language  A 원천 고정      LLM_JUDGED        → D 로 이동
confidence_* 6종           B 기계 계산      LLM_JUDGED        → D 로 이동
                                          (confidence_rating 만 ENGINE_OWNED)
```

**어떻게 잡혔는가** — 이 문서를 참조하는 도구형 프롬프트에
"문서와 코드가 다르면 코드가 정본이다" 를 넣어 두었고,
Codex(2026-08-14)와 Claude Code(2026-08-15)가 그 조항으로 이 문서를 잡았다.
게이트가 의도대로 작동한 사례다.

**남은 3중 불일치 — `review_required`**

```
부록 §4.3               기계 계산이라고 적음
schema.py               LLM_JUDGED_COLUMNS
build_bundle.compute_derived()   분리 생성 행에 'Y' 로 강제
```

세 곳이 서로 다르다. 코드 소유권(LLM_JUDGED)을 따라 D 에 두되,
분리 생성 행은 스크립트가 'Y' 로 덮는다는 사실을 함께 적는다.
어느 쪽이 옳은지는 sky 결정 사항으로 남긴다.
