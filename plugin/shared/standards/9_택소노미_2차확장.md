두 배치 연속으로 「기준서 미커버」가 이 네 곳에 몰렸다.

```
분리01   Codex 2건 · Claude Code 5건
분리02   Codex 7건 · Claude Code 6건   ← 미커버 전량이 신설 예정 4종
```

그리고 **라벨이 없으면 손실이 두 번 난다.**

> Claude Code 도구형 2026-08-15 —
> "라벨이 없어 미분류가 되면 **R17이 RootCause까지 N/A로 지웁니다.**
> 개선 요구가 명확한 발화인데 라벨 부재가 개선과제 소실로 이중 증폭됩니다."

**무엇을 고쳐야 하는지가 통째로 사라진다.** 확장이 늦어질수록 손실이 커진다.

```
   향하는 대상 = 폭발      →  안전(화재·감전·누수)
```

## 14. 긍정 나열은 기능별로 쪼갠다 — 단 「기대」 임을 함께 본다   【sky 결정 2026-08-25】

### ★★ 쪼갠 긍정은 「기대」 이지 「만족」 이 아닙니다


## 15. 「분리」 는 두 뜻으로 쓰입니다 — 갈라 쓰십시오   【sky 2026-08-25】

4차 실무자 의견에서 「분리」 가 **두 가지 다른 뜻**으로 쓰였습니다.
그래서 「분리 요구 19행」 이라고 셌는데 실제 행 분리는 **11행**이었습니다.

```
① 행 분리 (조각 나누기)
     한 댓글에 주제가 여럿이라 **행을 쪼갠다**
     「물걸레와 에러/오작동으로 분리」
     → 2차 분리제안 · 3차 감독 D 판정 · apply_split
     → 결과: 행이 늘어난다

② 라벨 분리 (갈라내기)
     한 라벨에 성격이 다른 것이 섞여 있어 **새 라벨로 갈라낸다**
     「출시 관련된 것에 대해 분리가 필요함」 (배송에서 출시를 갈라내라)
     → 기준서에 새 라벨을 적는다
     → 결과: 행 수는 그대로, 라벨만 바뀐다
```

★ **가름법 — 행이 늘어나는가.**

```
늘어난다  → ① 행 분리
그대로다  → ② 라벨 분리
```

★ 적으실 때 이렇게 써 주시면 헷갈리지 않습니다.

```
「A 와 B 로 **행을 나눠** 주세요」      ← ①
「C 를 **새 라벨로 갈라** 주세요」      ← ②
```

★ 셋째 뜻도 있습니다 — **병합(합치기)** 입니다.
  1차가 잘못 쪼갠 것을 2차가 합칩니다 (`structure.merge`).
  3차 감독은 `D` + `merge` 로 알립니다. 이건 「과분리」 라고 부릅니다.

## 16. 구체 라벨이 뭉뚱그린 라벨보다 낫다   【sky 결정 2026-08-26 · 45행】

한쪽이 `제품 전반` · `미분류` · `N/A` 처럼 뭉뚱그렸고 다른 쪽이 구체적이면
**구체 라벨을 쓴다.**

```
[제품 전반] vs [앱/스마트(원격제어)]   →  앱/스마트(원격제어)
[N/A]      vs [디자인]              →  디자인
```

★ 왜 — 집계에서 `제품 전반` 은 아무것도 알려 주지 않는다.
  §13(라벨 신설 자유)·§14(나열은 기능별로 쪼갠다) 와 같은 방향이다.

★ 다만 **정말로 제품 전반을 말하는 것**은 그대로 둔다.
  「이 제품 전체적으로 괜찮네요」 는 뭉뚱그린 것이 아니라 그것이 화제다.
