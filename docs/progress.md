  이미 적혀 나왔다. ★ **2026-10-29 에 다시 재어 보니 이 줄이 두 군데 틀렸다** —
  판독자가 받는 csv 는 74칸이 아니라 **79칸**(66 + 파생 8 + 사이드카 5)이고, 74칸은

- 사본은 검수 판정(`총괄검수_판정자리.csv`)이 빈 상태로 돈다 — 도구도 「검수 전 라벨로 셉니다」 라고 알린다
  (그래서 PL 위생 0행 · 편향검사 46.6% / 61.2%. 옛 문서의 57.3% / 51.5% 는 어느 시점 판정으로 잰 것인지 확인 못 함).
- 기준 사본의 기준서(`_판독패키지/1a·2·8·9`)는 **2026-09-18 판**(구독 절이 들어간 판)이다 — 최신판이 정본.

## 알게 된 함정

- 원본 도구들이 경로를 파일마다 박아 둠 → 섹션 2 에서 `paths.py` 한 곳으로 모은다.
- ★ **옛 배포 zip 은 최신이 아니다** (2026-09-18) — 09-18 에 다시 만든 판독 꾸러미에도 옛 판 파일 8개. 재료는 원본 자리에서 가린다.
- ★ **두 번 돌려 같다고 시각 칸이 없다는 뜻은 아니다** — 두 번이 같은 분 안에 끝나면 분 단위 시각이 우연히 같다.
  (데이터_넣기의 「만든 날」 을 스킬 시험에서야 잡았다.) 두 번 돌릴 때는 1분 이상 띄운다.
- 윈도에서 `claude` · `codex` 는 npm `.cmd` — 파이썬 subprocess 는 `shutil.which` 로 찾고, 한글 프롬프트는 표준입력으로 넘긴다.
- ★ 옛 3차 도구는 **자기 폴더와 부모 폴더까지** 뒤져 입력을 찾고, 찾은 감독 폴더에 안내 파일을 쓴다 (2026-09-18).
  사본은 부모가 빈 자리에서 돌려야 한다. 뒤에 생긴 백업 폴더(`_라벨바꾸기전_*`)도 2차 번들로 잡혀 멈췄다.
- ★ `ab_mapping.json` 에는 번들의 **전체 경로**가 적힌다 — 자리가 다르면 글자가 다르다. 맞댈 때 경로를 이름으로 바꾼다.
- 옛 도구 엔진 찾기: `VOC_ENGINE` 이 없으면 옛 엔진 자리로 간다(`check_selfcheck` · `엔진자리` · `build_bundle.build_xlsx`).
