>   꾸러미에 넣고 판을 올려야 한다 — sky 가 정한다.

## 한 줄로

유튜브에 **공개된 댓글**을 모아 쓰지만, 댓글에는 **작성자 이름 · 채널 ID** 가 붙어 오고 본문에 **전화번호 ·
이메일** 같은 것이 섞여 있을 수 있다. 그래서 「공개 자료니까 아무렇게나 써도 된다」 가 아니라,
**모은 목적(제품 VoC 분석) 밖으로 쓰지 않고, 사람을 짚어 내지 않고, 밖으로 낼 때는 치운 판본만 쓴다.**

## ① 어떤 정보를 쓰나 — 사실

| 정보 | 어디서 오나 | 어디에 남나 | 자리 |
|---|---|---|---|
| 댓글 **본문** (원문 · 대댓글 포함) | 유튜브 공식 API | 판 폴더 전체 — 1차 결과 · 판독 · 감독 · 총괄 · 최종 엑셀 · 살펴보기용 HTML | `plugin/engine/src/collectors/comments_collector.py:96-110` |
| 댓글 **작성자 이름** (`author_display_name`) | 같은 API | **1차 중간 파일(`.parquet`)에만** — 판독·감독·총괄 폴더와 아웃풋 1 에서는 찾지 못했다 | 같은 파일 `:107-108` · 2026-11-05 판 폴더에서 확인 (아래 「확인한 것」) |
| 작성자 **채널 ID** (`author_channel_id`) | 같은 API | 위와 같다 | 같은 파일 `:108` |
| 좋아요 수 · 올린 때 · 댓글 id | 같은 API | 판 폴더 전체 | 같은 파일 `:111-112` |
| 영상 제목 · 링크 · 채널 | 같은 API | 판 폴더 · 보고서 · 대시보드 | — |
| API 키 둘 (`YOUTUBE_API_KEY` · `OPENAI_API_KEY`) | 사람이 넣는다 | 윈도 사용자 환경변수 (`setx` — **평문**) | `0_빈컴퓨터에서_무엇을_깔까.md` ③ |

**댓글 본문에 섞일 수 있는 것** — 전화번호 · 이메일 · 다른 사람 계정(`@아이디`) · 링크 · 집 위치 · 구매처 ·
주문 정보 · 가족 이야기. 엔진에 이것을 **찾는** 도구가 있다 (`plugin/engine/src/utils/privacy.py` —
전화 · 이메일 · 링크 · `@계정`). 찾는 것이지 **댓글에서 지우는 것은 아니다.**

## ② 정보가 어디로 가나 — 사실

| 보내는 곳 | 무엇을 | 언제 |
|---|---|---|
| Google (유튜브 API · `googleapis.com`) | 검색어 · 영상 id | 1차 수집 |
| OpenAI (`api.openai.com` · gpt-4o-mini) | 댓글 본문 | 1차 분석 |
| Anthropic (Claude Code) | 판독·감독·총괄이 읽는 파일 내용 — 댓글 본문 포함 | 2 · 3 · 4차 |
| OpenAI (Codex) | 위와 같다 | 2 · 3차 |

- 코드가 직접 부르는 바깥 주소는 위 셋(`googleapis.com` · `api.openai.com` · 링크용 `youtube.com`)뿐이다.
  Claude Code · Codex 는 각자 자기 회사 서버로 간다.
- **MCP 를 쓰지 않는다** — 꾸러미 안에 MCP 설정이 하나도 없다 (2026-11-09 찾아봄). 실무자가 Claude Code 에
  따로 붙인 것이 있다면 그것은 이 꾸러미 밖의 일이다.
- 작성자 이름이 1차 분석 때 OpenAI 로 가는지는 **확인하지 않았다** (판독 쪽으로는 안 간다 — 위 표).

## ③ AI 가 어떤 권한으로 도나 — 사실

- Claude 는 `--dangerously-skip-permissions` 로 띄운다 — 파일을 고치거나 명령을 돌릴 때 **사람에게 묻지 않는다**
  (`한줄_돌리기.py` `AI돌리기`). 몇 시간씩 혼자 돌아야 해서 이렇게 했다.
- Codex 는 `workspace-write` — **작업 폴더 안에만** 쓴다.
- AI 기록(`<판자리>/기록/*.jsonl`)에는 AI 가 도구로 읽은 결과도 함께 적힌다 (2026-11-05 판의 판독 기록에서
  도구 결과 줄 77개를 셌다) — 그래서 **기록 파일에도 댓글 본문이 들어 있을 수 있다.**

## ⑤ 보안이 필요해 보이는 자리 — 권고

★ 아래는 **내 판단**이다. 회사 규정이 정해지면 그것을 따른다.

| 자리 | 왜 | 권고 |
|---|---|---|
| **판 폴더 통째** (`<판자리>`) | 원문 전량 · 작성자 이름(1차 중간 파일) · AI 기록이 다 있다 | 개인 PC 의 정해진 한 곳에만 둔다. 공유 드라이브 · 메신저 · 메일로 **폴더째 옮기지 않는다.** 분석이 끝나면 언제까지 두고 언제 지울지 정한다 |
| 1차 중간 파일 (`1차/engine/data/processed/**/*.parquet`) | **작성자 이름 · 채널 ID** 가 남는 유일한 자리 | 열어 보거나 따로 빼 쓰지 않는다. 지울 때 이것부터 |
| AI 기록 (`기록/*.jsonl`) | 댓글 본문이 섞여 있을 수 있다 | 비용을 셀 때만 쓰고, 남에게 보낼 때는 비용 숫자만 옮긴다 |
| 최종 엑셀 · 살펴보기용 HTML | 원문이 들어 있다 | **사내에서만.** 밖(협력사 · 외부 발표 · 고객사)으로는 **공유용 HTML · 사내 보고서만** |
| API 키 | 평문 환경변수 · 새면 남이 우리 이름으로 돈을 쓴다 | 사람마다 자기 키 · 키를 파일 · 메일 · 채팅에 적지 않는다 · 퇴사 · 이동 때 폐기 |
| AI 에게 보내는 것 | 댓글 본문이 Anthropic · OpenAI 서버로 간다 | 회사가 정한 AI 사용 지침(학습에 쓰이지 않는 계약 · 허용된 계정)에 맞는 계정으로만 돌린다 |
| 묻지 않고 움직이는 Claude | 판자리 밖 파일도 건드릴 수 있는 설정이다 | 회사 PC 에서는 판자리를 **빈 폴더**로 따로 두고, 중요한 파일이 있는 폴더 안에서 돌리지 않는다 |

## ⑥ 하지 않는 것 — 실무자가 지킬 선

1. **사람을 짚지 않는다.** 작성자 이름 · 채널로 특정인을 찾거나, 그 사람의 다른 댓글 · 채널을 따로 모으지 않는다.
2. **목적 밖으로 쓰지 않는다.** 제품 VoC 분석으로 모은 것을 마케팅 대상 목록 · 연락 · 다른 분석 재료로 쓰지 않는다.
3. **원문을 들고 나가지 않는다.** 밖으로 가는 것은 공유용 HTML 과 사내 보고서뿐이다. 그 밖의 것을 밖으로
   내야 하면 먼저 묻는다.
4. **댓글 속 개인정보를 옮겨 적지 않는다.** 보고서 · 발표 · 메일에 댓글을 인용할 때 전화 · 이메일 · 계정 · 이름을 빼고 적는다.
5. **키를 나누지 않는다.** 키 값을 적거나 보내지 않는다.
6. **끝나면 치운다.** 판 폴더를 언제까지 둘지 정하고 지난 것은 지운다 (특히 1차 중간 파일과 AI 기록).

## ⑦ 보안 담당자가 물을 것 — 답할 재료

회사 양식이 오면 아래를 옮겨 적으면 된다. 답은 위 ①~④ 에 있다.

| 물을 것 | 답 |
|---|---|
| 어떤 개인정보를 다루나 | 공개 댓글 본문 · 작성자 이름 · 채널 ID (①) |
| 어디로 보내나 | Google · OpenAI · Anthropic (②) |
| MCP 를 쓰나 | 꾸러미에는 없다 (②) |
| AI 의 권한은 | Claude 묻지 않음 · Codex 작업 폴더 안만 (③) |
| 어디에 저장하나 · 얼마나 두나 | 실무자 PC 의 판 폴더 · **기간은 아직 정하지 않았다** (⑤) |
| 밖으로 나가는 결과물은 | 공유용 HTML · 사내 보고서 — 치우고 다시 훑는다 (④) |
| 키는 | 사람마다 · 평문 환경변수 (①) |
