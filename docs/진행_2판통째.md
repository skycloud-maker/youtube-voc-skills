## 1. 무엇을 재는가 — 한 줄

**2차·3차 AI 판정이 옛 2판의 판정과 같은가.**

이미 잰 것과 **다르다.** 2026-10-29 에 잰 **100.00%** (행 6,846 · 칸 89 · 다른 칸 0)
는 「**도구**가 옛 도구와 같은 일을 한다」 는 것만 말한다 — 단계별 대조는
AI 판정을 **옛것으로 고정**하고 도구만 댔기 때문이다
(`docs/decisions/0011` · `tests/test_옛판대조.py`).
**AI 가 같은 판정을 하는가**는 처음부터 끝까지 다시 돌려야 나온다. 그것을 지금 돌린다.

## 3. 1차는 다시 돌리지 않는다 — 왜

옛 댓글을 **다시 모을 수 없다.** 지워진 댓글이 있고 새로 달린 댓글도 있어서, 같은
검색어로 다시 모으면 **모수가 달라진다.** 그러면 「AI 판정이 같은가」 를 재는 것이
아니게 된다. 그래서 **2판의 1차 결과를 그대로 2차 입구에 앉히고** 거기서 돌린다.

| 앉힌 것 | 자리 | 크기 |
|---|---|---|
| 1차 번들 | `C:\voc_2판통째\1차\engine\outputs\voc_dashboard_60\2판통째\voc_dashboard_export_bundle (14).xlsx` | 행 **6,336** · 칸 74 · 영상 **65** · 시트 6 |
| 영상메타 | 같은 폴더의 `7_영상메타.csv` | 영상 **21개** |

★ 영상메타가 21개뿐인 것은 **옛 2판도 그랬다** — 꾸러미 견본과 `video_id` 21개가
  전부 같다(세어 확인했다). 2판을 그대로 재현하는 것이므로 **고치지 않는다.**

## 4. ★ 행이 늘어난다 — 「100%」 가 무엇을 뜻하는지

```
1차 입력   6,336 행
옛 최종    6,846 행      ← 510 행이 뒤에서 늘어난다
```

3차 **D 판정**(「둘 다 맞다 — 나눠야 한다」)과 4차 반영이 행을 **쪼갠다.**
그래서 **행까지 100% 같으려면 쪼개는 판단까지 같아야** 한다.
sky 가 미리 말한 그대로다 — 「100프로 맞는게 아니고 일부 데이터 좀 차이가 생길수는
있지만」. 그 차이가 **몇 % 인지**를 내는 것이 이 실행의 결과물이다.

대조 도구는 행이 달라도 센다 — `양쪽` · `옛에만` · `새에만` 과 묶음별 %
(`tools/옛판_결과대조.py`).

## 5. 깃발 — `--깨끗` 을 쓴다 (왜)

결정 0006 §6 — 「사내 자리는 내 컴퓨터보다 헐벗다 … 사내에 주기 전에 **깨끗한
자리에서 다시 돌려 보는 것이 순서다.**」 내 컴퓨터의 전역 작업규칙과 훅이
판독자 머리에 먼저 들어가면 「스킬만 줘도 되는가」 를 재는 것이 아니게 된다.
`--깨끗` = `--setting-sources "" --strict-mcp-config` (우리 스킬 6개는 그대로 보인다).

## 8-4. 판독A 가 스스로 적어 놓은 것 (3차에서 볼 거리)

판독A 의 마지막 답에 있던 말이다. **고치지 않고 그대로 옮긴다** —

- 「성실성검사가 01~03회차의 **원인(rootcause) 채운 비율이 낮다**고 표시합니다
  (10% · 17% · 17%, 이후 50~100%). 막는 신호는 아니지만 사실입니다 — 초반에는 1차의
  rootcause 를 그대로 둔 행이 많았고, 04회차부터 해석 여지를 원문에서 다시 쓰는 쪽으로
  손이 굳었습니다. **3차에서 01~03을 다시 볼 때 이 점을 감안해 주십시오.**」
- 「검증이 V-0-2 `column_set_or_order_mismatch`(74 vs 66)로 떨어집니다. 값 위반은 0건입니다.」
  → 1차 번들 `raw_voc` 는 **74칸**이고 66칸 계약으로 검사해서 난 것이다
  (칸 사슬 66 → 74 → 79 → 89). 판독A 는 「1회차 때 한 번 돌린 번들 검증 잔재이고
  산출물이 아니다」 라고 적었다. **막지 않았다.**
- `--drift` 표류② — 「「보안」 어휘가 4라벨로 흩어진 것을 경고하는데, 그중 5건은 제외 행의
  N/A(「다15」대로)이고 나머지는 주절이 화재인 행입니다.」
