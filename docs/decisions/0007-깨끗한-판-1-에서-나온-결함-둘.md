## 5. 결함 둘 — **둘 다 고쳤다**

### 결함 ① 칸 검수가 **눈먼 길**로 떨어진다 — yaml 이 없는 파이썬에서

- 증상 — `check_selfcheck` 가 안 깨진 번들을 「✗ 번들에서 빠진 칸 2 — video_tags /
  video_description · 엔진 스키마를 손댄 사람이 있다」 로 **잘못 반려**했다.
  판독B 가 「자체검사 1건이 반려됐습니다」 로 적어 보냈다.
- 까닭 — `_일차가_내놓는가()` 가 `from src.voc_rebuild import schema` 로 **꾸러미**를 불러왔다.
  그 `__init__.py` 가 `.engine` 을 불러오고 → `config.py` → `yaml` 로 내려간다.
  **Codex 내장 파이썬에는 yaml 이 없다** (pandas 3.0.1 · openpyxl 3.1.5 는 있다).
  2026-10-09 에 pandas 때문에 그 파이썬을 PATH 앞에 놓았으므로, 판독자·감독자는 바로 그 파이썬을 쓴다.
  import 가 터지면 `return True` — 「엔진을 못 보면 예전대로 반려한다」 로 떨어진다.
- ★ 2026-10-09 의 고침(`VOC_ENGINE` 주기)으로는 **막히지 않는다.**
  가리키는 것과 **불러오는 것**은 다른 일이다. 그래서 그 시험은 통과하면서 실제로는 터졌다.
- 고침 — `schema.py` **파일 자리로 바로 읽는다** (`importlib.util.spec_from_file_location`).
  그 파일은 json · typing 만 쓴다. yaml 이 필요 없다.
  그리고 **끝까지 못 보면 크게 말한다** — 「가르지 못했습니다 · 아래 ✗ 는 그대로 믿지 마십시오」.
- 확인 — yaml 을 가리고 `VOC_ENGINE` 도 안 준 자리에서 `✗ 1건 → ✗ 0건`.
  엔진을 아예 치운 자리에서는 귀띔이 뜨고 ✗ 는 남는다 (조용히 통과하지 않는다).

### 결함 ② 갖춤새 점검이 **총괄 파이썬만** 봤다

- 증상 — 판독B 가 XLSX 번들과 계약·제출 검사를 못 만들고 CSV 만 내놓았다.
  미리 알릴 길이 없었다 (`--확인만` 은 「다 됐습니다」 였다).
- 까닭 — `갖춤새_점검` ① 이 `pandas`·`openpyxl` 을 **총괄이 돌아가는 파이썬**에서만 봤다.
  판독자·감독자가 쓰는 Codex 내장 파이썬은 아무도 안 봤다. yaml 은 목록에도 없었다.
- 고침 — 목록에 `yaml` 을 넣고, codex 쪽 자리를 부를 때 **그 파이썬에 직접 물어본다**
  (`find_spec` 으로 본다 — 불러오면 없는 것이 가려진다). 넣는 명령을 그대로 적어 준다.
- ★ **멈추지는 않는다.** yaml 이 없어도 CSV 번들은 나왔고 2차·3차는 그 CSV 로 갔다.
  하드로 막으면 받은 사람은 되는 흐름을 0단계에서 세운다. 그래서 「귀띔」 으로 매번 크게 적는다.

```
  갖춤새 — 다 됐습니다 (꾸러미 · 명령 · 키)
  ! Codex 내장 파이썬에 꾸러미가 없습니다 — yaml · 자리: 판독B · 감독1
       넣기 — "...\codex-primary-runtime\dependencies\python\python.exe" -m pip install pyyaml
       안 넣으면 — codex 쪽 판독자는 XLSX 번들과 계약·제출 검사를 못 만듭니다 (CSV 는 나옵니다)
```
