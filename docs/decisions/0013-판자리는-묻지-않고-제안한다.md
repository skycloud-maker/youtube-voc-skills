# 0013 — 판자리는 **묻지 않고 제안한다**

> 정한 날 2026-11-04 · 정한 사람 **sky** · 고른 것 **ㄱ**
>
> 나온 자리 — ④ 새 채팅방 시험 중 sky 물음:
> 「근데 원래 판자리라는걸 대답하게 되어있는지..? skill 로 가져가서 다른 실무자도
> 이렇게 답하는것인지?」

## 무엇이 문제였나

새 채팅방이 스킬을 집고 **맨 먼저 판자리(결과를 쌓을 폴더)를 물었다.** 설계대로다 —
[`coordinating-voc-pipeline/SKILL.md`](../../plugin/skills/coordinating-voc-pipeline/SKILL.md) 의
「돌리기 전에 — 묻고 보여 준다」 1번이 **「판자리를 어디에 차릴지 묻는다」** 다.

그런데 **판자리는 실행조건 열 칸이 아니다.** `shared/common/99_1차_실행조건_원문.md` 에
「판자리」 는 **0건**이다. 즉 열 칸과 별개로 사람에게 **윈도 경로를 적게 하는 질문**이 하나 더 있다.

실무자에게는 무리다. 「판자리」 라는 말도, 「저장소 밖이어야 한다」 는 까닭도 모른다.
스킬로 업무를 넘긴 뜻은 **사람이 내부 사정을 모른 채로도 되게** 하는 것이다.

## 정한 것 — ㄱ

**AI 가 자리를 제안하고, 사람은 「네」 만 하면 된다.** 다르면 그때 말한다.

```
지금    「판자리를 어디에 차릴까요?」
          → 사람이 C:\... 를 적어야 한다

고치면  「C:\작업\VoC_판\2026-11_LG로봇청소기 에 차리겠습니다.
          다른 자리를 쓰시려면 말씀해 주십시오」
          → 「네」 한 마디
```

★ **왜 AI 가 정해도 되나** — 사람이 정해야 하는 것은 「저장소 밖」 이라는 **제약**뿐이고,
  그건 **규칙이지 선택이 아니다.** 규칙은 도구가 지키면 된다.

★ **제안한 자리를 그대로 찍어 보여 준다.** 사람이 안 보고 넘겨 엉뚱한 자리에 쌓이는 것을
  이것으로 막는다 (ㄱ 의 유일한 위험이었다).

## 안 바꾸는 것

- **실행조건 열 칸은 그대로 묻는다.** 돈이 드는 칸이라 사람이 정해야 한다
  (2026-10-22 재점검 · sky).
- **「저장소 밖」 제약은 그대로다.** 1차 엔진이 결과를 자기 폴더 아래(`data/` · `outputs/`)에
  쓰기 때문이다. 제안하는 자리도 저장소 밖이어야 한다.
- **결과 숫자는 한 칸도 안 바뀐다.** 사람에게 말하는 방식만 바꾼다 —
  그래서 **동결 3b 와 섞이지 않는다.**

## 언제 — **④ 새 채팅방 시험이 끝난 뒤**

지금(시험 중) `plugin/` 을 고치면 꾸러미 캐시가 어긋나 **다시 깔고 앱을 또 재시작**해야 한다
(꾸러미가 저장소가 아니라 캐시 사본에서 뜨는 것은 → [지금 어디인가](../지금_어디인가.md)).
시험이 중간에 깨지므로 미룬다.
