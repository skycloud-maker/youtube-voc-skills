# 결정 0001 — 이 저장소는 옛것과 엮지 않는 독립된 새 출발이다

날짜: 2026-09-18 · 정한 사람: sky

## sky 말씀 (원문)

> 새 저장소는 정말 그냥 새로 github repo도 만들고, 새로 streamlit에 사이트도 만들거고.. 그런용도입니다.
> 진짜 이전에 있떤건 그대로 놔두고(왜냐하면 새로 구현하다 오류가나서 아예 안되면 다시 이전걸 써야하니까요),
> 새로 만들어서 제로에서 깔끔하게 세팅을 하기위한것이라고 보시면 됩니다.
> 굳이 기존폴더와 엮어서 계속 동시에 작업되도록 할 필요는 저는 없다고 생각합니다..

## 그래서 지키는 것

1. **옛것은 예비다.** `youtube-comment-analyzer` 저장소, `C:\codex`, `C:\codex_live_merge`,
   지금 운영 중인 Streamlit 사이트는 그대로 둔다. 새 구현이 안 되면 옛것으로 돌아간다.
2. **옛 폴더는 한 번 복사할 때만 읽는다.** 복사한 뒤에는 새 저장소의 어떤 코드·스킬·시험도
   옛 폴더 경로를 부르지 않는다. 옛 경로(`C:/codex...`)가 코드에 남아 있으면 결함이다.
3. **출처는 기록한다.** 무엇을 어느 커밋에서 복사했는지는 `docs/sources/` 와 각 문서 머리에 남긴다.
   이것은 기록이지 연결이 아니다.
4. **시험의 기준 정답도 복사해서 둔다.** 옛 도구를 실행해서 맞대지 않는다.
   옛 결과물 가운데 기준으로 삼을 것을 한 번 복사해 이 저장소 안(개인정보 가림)에 두고,
   새 도구의 결과를 그것과 맞댄다.
5. **Streamlit 사이트도 새로 만든다.** 옛 사이트를 고치지 않는다.
6. 새 대시보드와 새 스킬이 같이 쓰는 기본값·설정은 **이 저장소 안의 한 파일**에 둔다.

## 이 결정으로 바뀐 것

- `docs/ROLES.md` 의 「기본값은 대시보드와 스킬이 같은 파일을 본다」 →
  「이 저장소 안의 새 대시보드와 새 스킬이 같은 파일을 본다」.
- `docs/progress.md` 섹션 2 — 옛 도구를 실행해 맞대기 → 옛 결과물을 한 번 복사한 기준 정답과 맞대기.
- `docs/progress.md` — 새 Streamlit 사이트 섹션을 더한다.
