  나는 「돌리개가 헛통과했다」 고 적었다. **틀렸다.** 세어 보니 그 18행의
  `(atomic_id, status)` 는 **우리 수정로그에 제안으로 18/18 있었고, 내가 승인한 것은
  0/18** 이었다. 돌리개는 **승인된 것만** 검사하므로 제대로 통과한 것이다.

  내가 왜 승인하지 않았나 — 옛 수정로그의 표기를 잘못 읽었다. 옛 파일은
  `field` 에 `status/topic` 처럼 **쌍**을 적고 `새값` 에는 한 값을 이 표기로 적는다 —

  ```
  field = status/topic   새값 = 제외(operator_notice)
      → status = scope_excluded · scope_exclusion_reason = operator_notice · topic = N/A
  field = status/topic   새값 = 제품 전반
      → topic = 제품 전반 · status = normal
  ```

  나는 `/` 로 가르고 **같은 `새값` 을 두 칸에 다** 댔다. 그러니 `status` 의 제안값
  `scope_excluded` 가 `제외(operator_notice)` 와 글자로 같을 수 없어 **반려로
  떨어뜨렸다.** 사람이 정한 것을 내가 버린 것이다.

  고쳤다 — `tools/4차_사람결정_넣기.py` 의 `표기_풀기()` 가 그 표기를 푼다
  (`tests/test_4차_사람결정_넣기.py::test_옛_표기를_제대로_푼다` ·
  `::test_제외로_정한_행을_승인한다` 가 지킨다).
  고치고 다시 넣으니 **승인이 222 → 347 (+125)** 로 늘었다.

★ **총괄 AI 가 제 손으로 찾아 적었다** — 이것이 이번에 가장 값진 대목이다.
  내가 떨어뜨린 사람 결정을 AI 가 **옛 결정과 대보고** 찾아 파일로 남겼다.
  다만 **돌리개가 그 파일을 읽지 않는다** — 사람이 열어 봐야 안다. 그것은 고칠 거리다.

## 3. 그래서 — 「완성본인가」 에 대한 답

| 물음 | 답 |
|---|---|
| 꾸러미 순서대로 끝까지 도나 | **그렇다.** 1차(앉힘) → 2차 둘 → 총괄검수 → 3차 준비 → 감독 둘 → 마무리 → 아웃풋1 → 4차. 사람이 창을 열거나 붙여넣은 적 **0번** |

| 도구가 2판과 같게 동작하나 | **그렇다.** 24칸 처리까지 옛것과 같다 (회귀 없음) |
| 값이 2판과 같나 | **칸마다 46~100%.** 규칙이 분명한 칸 90~100% · 해석 칸 46~59% · 자유서술은 애초에 낱말 일치를 기대할 수 없다 |
