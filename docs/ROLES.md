「운영자」 와 「시스템 담당자」 는 사람은 같아도 역할 이름을 나눠 둔다 —
AI 에게 「고치지 말고 시스템 담당자에게 전달하라」 고 시키기 위해서다.

## 받는 것 — 스킬은 AI 가 읽는다. 사람에게는 안내서를 준다

| 받는 쪽 | 받는 것 |
|---|---|
| 1차 실행 AI | 스킬 `running-voc-engine` — 실행조건서를 빈칸마다 묻고 → quota·비용 확인 → 실행 → 조건서를 결과와 함께 저장 |
| 2차 판독 AI | 스킬 `reading-voc-comments` |
| 3차 감독 AI | 스킬 `supervising-voc-disagreements` |
| 총괄 AI | 스킬 `coordinating-voc-pipeline` |
| 운영자 · 4차 실무자 | 안내서 `guides/` + 대시보드(결과 보기) |
| (마지막 섹션) 결과 보기 | 스킬 `building-voc-report` — 최종 결과로 사내에서만 여는 HTML 보고서 생성 |

공통 기준(기준서·택소노미·Enum·대장·공통 도구)은 스킬마다 복사하지 않고 `plugin/shared/` 한 벌을 쓴다.

## 실행조건서 — 대시보드 입력 화면을 대신한다

출처: 원본 `src/dashboard60/analysis_runner.py` 의 입력 칸.

- 입력 유형: 정리된 폴더 / 원본 파일 / YouTube 새로 모으기
- YouTube: 키워드(줄마다) · 결합 OR/AND · AND 최소 일치 수 · 게시일 시작·끝 ·
  국가 KR · 언어 ko · 영상 수(기본 2, 최대 500) · 영상당 댓글(기본 10, 0=전부) ·
  대댓글(기본 예) · 채널 ID(선택)
- 분석: 최대 행수(기본 20) · 묶음 5 · 묶음 대기 120초 · 모델(비우면 gpt-4o-mini) · 실행 이름
- 막는 것: quota 예상치 · 「전부」 경고 · API 키 확인 · **명시적 실행 동의 없이는 돌리지 않는다**
- 키워드처럼 정답이 없는 칸은 기본값을 쓰지 않고 반드시 묻는다
- AND 는 맨 윗줄로만 검색하고 아랫줄은 제목·설명·채널명·태그의 **글자**로 거른다
  (후보 200~300개) — 고르면 AI 가 줄 순서를 확인받는다
- 기본값·최댓값은 대시보드와 스킬이 같은 파일을 본다 (두 벌 금지)
