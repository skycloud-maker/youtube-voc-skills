# 역할 지도 — 누가 무엇을 하고, 어느 스킬을 받나

업무 흐름 (원본 저장소 CLAUDE.md · sky 2026-08-24 기준):

```
1차 엔진 판정 → 2차 판독자 LLM 둘 → 3차 심판 LLM 둘 → 담당자 통합 → 4차 사람 검토 → 대시보드
```

요점 — **답이 갈리는 곳이 곧 사람이 볼 곳이다.** 그래서 판독자 둘·심판 둘을 같은 조건으로 돌린다.

| 역할 | 하는 일 | 받는 스킬 | 하지 않는 것 |
|---|---|---|---|
| 엔진 운영자 | 댓글을 모아 1차 엔진으로 판정 | `running-voc-engine` | 엔진 코드를 고치지 않는다 (동결) |
| 2차 판독자 (둘) | 1차 결과를 기준서대로 판독 → 자기 폴더에 번들 | `reading-voc-comments` | 다른 판독자의 답을 보지 않는다 |
| 3차 심판 (둘) | 판독이 갈린 행만 판정 | `supervising-voc-disagreements` | 통합하지 않는다 · 다른 심판 결과를 찾지 않는다 |
| 담당자 | 두 폴더를 받아 통합 → 꾸미기 → 차수 넘김 판단 | `coordinating-voc-pipeline` | 판정을 대신하지 않는다 |
| 4차 검토자 (사람) | 사람이 볼 목록·보정 요청을 정한다 | `reviewing-voc-results` | — |
| 실무자 | 대시보드로 결과를 본다 | `viewing-voc-dashboard` | — |

공통 기준(기준서·택소노미·Enum·검사 규칙)은 스킬마다 복사하지 않고 `plugin/shared/` 한 벌을 쓴다.

> 이 표는 설계안이다. 각 스킬을 지으면서 실제 도구·문서와 맞춰 고친다.
