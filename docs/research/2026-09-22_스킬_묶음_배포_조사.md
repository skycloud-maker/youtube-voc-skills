# 스킬을 파일 하나로 묶어 배포할 때의 공식 규칙 (읽기 전용 조사, 파일은 만들거나 고치지 않음)

## 결론
- `.skill` 파일은 확장자만 바꾼 **zip 파일**이다. 그 안의 맨 위(루트)에는 **스킬 폴더 하나**가 있어야 한다: `<name>/SKILL.md`, `<name>/scripts/...`
- 스킬 창작 도구(skill-creator)의 공식 묶기 스크립트는 다음을 뺀다.
  - 스킬 폴더 바로 아래의 `evals/`
  - 어느 깊이에 있든 `__pycache__/`, `node_modules/`, `*.pyc`, `.DS_Store`
- 플러그인과 claude.ai 모두 **자기 폴더 밖의 파일을 가져가지 않는다.** 그래서 `../../shared/...` 방식은 따로 떼어 낸 스킬에서 동작하지 않는다. `shared` 폴더는 각 스킬 폴더 안으로 복사하고, 본문과 스크립트의 경로도 그에 맞게 바꿔야 한다.

## 출처 3 — Claude Code 문서 (스킬 · 플러그인)
**URL**
- https://code.claude.com/docs/en/skills
- https://code.claude.com/docs/en/plugins-reference

**문서가 말한 것 (원문 인용)**
- `${CLAUDE_SKILL_DIR}`: "For plugin skills, this is the skill's subdirectory within the plugin, not the plugin root."
- 플러그인 스킬에서는 `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`도 본문과 `allowed-tools` 안에서 치환된다.
- 플러그인은 폴더 밖 파일을 참조할 수 없다: "Claude Code doesn't let a plugin reference files outside its own directory." 이런 경로는 `path escapes plugin directory` 오류가 난다.
- 설치 때도 밖의 파일은 따라오지 않는다: "doesn't copy files outside the plugin directory into the cache"
- 마켓플레이스 안에서는 공유 파일을 심볼릭 링크(symlink, 다른 파일을 가리키는 바로가기 파일)로 둘 수 있다. 같은 마켓플레이스 안을 가리키는 링크는 실제 내용으로 바꿔 복사된다. 마켓플레이스 밖을 가리키는 링크는 건너뛴다.
- claude.ai에서 동기화되어 온 스킬은 일부 세션에서 `@` 참조, `!` 명령, `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_SESSION_ID}`가 "reach Claude as literal text" 된다. 즉 **변환되지 않은 글자 그대로** 전달된다.
- Claude Code는 claude.ai 업로드용 형식에 없는 frontmatter 키도 쓴다: `when_to_use`, `arguments`, `context`, `model`, `effort`, `hooks`, `paths`, `shell` 등.
- 폴더 이름 `synced`는 예약되어 있다.
- **확인되지 않은 것:** 처음 받은 요약에 "Skills should not reference files outside their folder" 라는 문장이 있었다. 다시 확인하니 **그 문서에 없는 문장**이었다. 요약 도구가 지어낸 것이라 인용하지 않는다. 폴더 밖 참조 금지의 근거는 위 플러그인 문서다.

## 출처 4 — evals 폴더
- skill-creator의 묶기 스크립트는 스킬 루트의 `evals/`를 명시적으로 뺀다 (위 코드의 `ROOT_EXCLUDE_DIRS`).
- `claude plugin eval` (https://code.claude.com/docs/en/plugin-evals) 은 **플러그인 루트의 `evals/`** 에 시험 사례를 둔다.
  - 설치된 플러그인에 대해서도 "The cases in the installed copy's eval directory" 를 돌린다. 곧 플러그인에서는 evals가 함께 배포된다는 뜻이다.
  - 두 도구의 형식은 "aren't interchangeable", 서로 바꿔 쓸 수 없다.
- Codex (https://learn.chatgpt.com/docs/build-skills, https://github.com/openai/codex/blob/main/docs/skills.md)
  - 저장소 위치는 `.agents/skills`, 사용자 위치는 `$HOME/.agents/skills` 이다.
  - 필수 항목은 `name`, `description`. 선택 항목으로 `agents/openai.yaml`이 있다.
  - 심볼릭 링크를 따라간다.
  - 글자 수 한도는 확인하지 못했다.

## 내 추론 (출처가 직접 말한 것은 아님)
1. `.skill`과 `.zip`의 내부 구조는 같다. claude.ai는 zip 업로드를 공식으로 안내한다. 그래서 둘 다 만들거나 `.zip`을 기본으로 두는 편이 안전하다. `.skill` 확장자를 claude.ai 업로드 창이 직접 받아 주는지는 공식 문서에서 확인하지 못했다.
2. 스킬별 묶음에서 evals를 뺄지 넣을지는 **sky가 정할 일**이다. 공식 묶기 스크립트를 따르면 뺀다. 플러그인과 Codex 사본에는 남겨도 문제가 없다.
3. 따로 떼어 낸 스킬에서는 `${CLAUDE_PLUGIN_ROOT}`가 치환되지 않는다. 따라서 본문과 스크립트의 공유 경로를 **스킬 폴더 기준 상대경로**로 바꿔 써야 한다. 스크립트는 `__file__` 기준 경로를 쓰는 것이 좋다.
4. 설명 글자 수는 1024자(API·개요·스크립트)와 200자(고객센터)가 충돌한다. 도구에서 200자 초과는 **경고**, 1024자 초과는 **실패**로 두기를 권한다.

## 빌드 도구가 지켜야 할 규칙
1. **zip 구조:** zip 루트에 `<name>/` 폴더 하나만 둔다. 그 바로 아래에 `SKILL.md`(대문자)를 둔다. zip 안의 경로 구분자는 `/`로 쓴다.
2. **폴더 이름:** 폴더 이름과 frontmatter의 `name`이 정확히 같아야 한다.
3. **빼는 파일**
   - 어느 깊이든: `__pycache__/`, `node_modules/`, `*.pyc`, `.DS_Store`
   - 스킬 루트의 `evals/` (claude.ai용)
   - 권장(공식 목록에는 없음): `*-workspace/`, `Thumbs.db`, `.git`
4. **공유 파일:** `shared`를 각 스킬 안으로 복사한다. 복사 뒤에는 결과물 전체에서 `../`로 폴더 밖을 벗어나는 참조와 `${CLAUDE_PLUGIN_ROOT}` 참조를 검색한다. 하나라도 남으면 **실패**로 처리한다.
5. **frontmatter 검사**
   - 첫 줄이 `---`이고 YAML 사전 형식이어야 한다.
   - 허용 키는 `name`, `description`, `license`, `allowed-tools`, `metadata`, `compatibility`뿐이다 (claude.ai 묶음 기준). 고객센터 문서의 `dependencies`는 skill-creator 검사기에서 거부된다.
   - `name`: `^[a-z0-9-]+$`, 1–64자, 앞뒤 `-` 금지, `--` 금지, `anthropic`·`claude`를 포함하면 안 되고, `synced`이면 안 된다.
   - `description`: 비어 있지 않을 것, 1024자 이하, `<`·`>` 금지.
   - `compatibility`: 500자 이하.
6. **용량:** 압축을 풀었을 때 30MB 미만 (API 기준. claude.ai 한도 숫자는 공개되어 있지 않다).
7. **권고 수준 경고:** SKILL.md 본문 500줄 이하, 경로에 백슬래시 금지.
8. **Codex 사본:** `.agents/skills/<name>/`에 같은 내용을 두고, 같은 검사기를 돌린다.

## 확인하지 못한 것
- claude.ai 업로드의 실제 용량 한도와 파일 개수 한도
- claude.ai가 `.skill` 확장자를 직접 받는지
- 소문자 `skill.md` 표기가 실제 업로드에 영향을 주는지
- Codex의 글자 수 한도

## 섹션 6 이 따른 것 (이 저장소의 결정 · 2026-09-22)

- 묶음 = zip 맨 위에 `<name>/` 하나 (package_skill.py 와 같은 구조). 파일은 `dist/claude/<name>.zip` — claude.ai 가 공식으로 안내하는 것이 zip 이라서다.
  `.skill` 은 확장자만 다른 같은 파일이다(필요하면 이름만 바꾼다).
- `shared/` · `engine/` 은 스킬마다 안에 복사한다. 총괄 스킬은 판독 · 감독 스킬의 references · assets 도 `skills/<이름>/` 에 넣는다 —
  세 스킬의 차리기 스크립트가 이미 「스킬 안 → 플러그인 옆」 차례로 찾도록 짜여 있다(섹션 4 · 5).
- 빼는 것: 어느 깊이든 `__pycache__` · `*.pyc` · `.DS_Store` · `node_modules`, 스킬 맨 위 `evals/` (공식 묶기 도구대로),
  그리고 `shared/paths.py` (이 컴퓨터 경로가 적힌 개발용 파일 · 나가는 코드가 부르지 않는다).
- 검사(묶을 때마다 · 실패하면 안 묶는다): frontmatter(quick_validate 규칙 + 예약어 · 폴더 이름 일치) · 용량 30MB 미만 ·
  설명 200자 초과는 경고(고객센터) · 1024자 초과는 실패.
- Codex 사본 = `dist/codex/.agents/skills/<name>/` 에 같은 내용 (섹션 3a 결정 「조립 도구가 복사」).
- 「../ 로 폴더 밖을 벗어나는 참조를 검색해 실패」 는 글자 검색 대신 **실제로 돌려 본다** — 묶은 스킬을 플러그인과 떨어진 빈 자리에 풀고
  차리기 스크립트를 돌려 재료를 하나도 빠짐없이 스킬 안에서 찾는지 본다 (SKILL.md 의 `../../shared` 는 플러그인 안일 때의 안내라 글자로는 남는다).
