## 보고 원문

Codex는 SKILL.md 스킬을 지원합니다. 같은 스킬 폴더를 Claude와 같이 쓰는 공개 사례는 폴더 심볼릭 링크 방식이 가장 흔합니다. 한국어 스킬 이름은 읽기는 될 가능성이 높지만 `$` 로 부르기는 막힐 가능성이 높습니다(코드 읽기로 한 추론이고, 실행해 보지는 않았습니다). 파일은 만들거나 고치지 않았고, 원문은 scratchpad 로 받아서 읽기만 했습니다.

#### 2. 스킬을 찾는 폴더
공식 문서의 표를 그대로 옮긴다.

| 범위 | 위치 |
|---|---|
| REPO | `$CWD/.agents/skills` |
| REPO | `$CWD/../.agents/skills` |
| REPO | `$REPO_ROOT/.agents/skills` |
| USER | `$HOME/.agents/skills` |
| ADMIN | `/etc/codex/skills` |
| SYSTEM | Bundled with Codex |

- 저장소 안 탐색 범위 — "scans `.agents/skills` in every directory from your current working directory up to the repository root"
- 심볼릭 링크 — "Codex supports symlinked skill folders and follows the symlink target"
- 이름이 겹칠 때 — "If two skills share the same `name`, Codex doesn't merge them; both can appear"

코드(`host_roots.rs`)에는 문서에 없는 자리가 더 있다.
- `$CODEX_HOME/skills`, 즉 `~/.codex/skills` 를 읽는다. 주석 원문: "Deprecated user skills location (`$CODEX_HOME/skills`), kept for backward compatibility."
- 프로젝트 설정 폴더 아래 `skills` 도 REPO 범위로 읽는다. 이 설정 폴더는 `.codex/` 일 것이다(추론).
- `.claude/skills` 라는 문자열은 openai/codex 코드 검색에서 한 건도 나오지 않았다. 따라서 Codex 가 이 폴더를 직접 읽는다는 근거는 못 찾음.

코드(`host.rs`)의 심볼릭 링크 처리:
- User·Repo·Admin 범위는 `DirectorySymlinkPolicy::Follow` (링크를 따라간다).
- System 범위는 `Ignore` (따라가지 않는다).
- 점(.)으로 시작하는 숨은 하위 폴더는 건너뛴다(`HiddenDirectoryPolicy::Skip`).

#### 3. 규격

**공식 문서** — "The `SKILL.md` file must include `name` and `description`."
- Codex 문서에는 길이나 문자 제한이 적혀 있지 않다.

**Codex 코드**
- `MAX_NAME_LEN: usize = 64`
- `MAX_DESCRIPTION_LEN: usize = 1024`
  - 이 상수는 `agents/openai.yaml` 의 interface·의존성 필드 검사에 쓰인다.
  - SKILL.md 의 description 에 대해서 `parser.rs` 는 비어 있지 않은지만 본다: `if description.is_empty() { return Err(... MissingField("description")) }`
- `MAX_QUALIFIED_NAME_LEN = MAX_NAME_LEN * 2 + 1` — 플러그인 이름을 앞에 붙인 이름은 최대 129자다.
- 탐색 한도: `MAX_SCAN_DEPTH: usize = 6`, `MAX_SKILLS_DIRS_PER_ROOT: usize = 2000`
- 길이는 `value.chars().count()` 로 센다. 바이트가 아니라 글자 수라는 뜻이다.
- `name` 이 비어 있으면 상위 폴더 이름을 대신 쓴다(`default_skill_name`).
- 소문자·하이픈 문자 검사나 폴더 이름 일치 검사는 `parser.rs` 에서 못 찾음. Codex 가 이 둘을 강제하지 않는 것으로 보인다(추론). 파일 전체를 다 대조하지는 않았다.

**agentskills.io 표준**
- `name`: "Max 64 characters. Lowercase letters, numbers, and hyphens only." / "Must match the parent directory name" / "Must not contain consecutive hyphens"
- `description`: "Max 1024 characters. Non-empty."
- `compatibility`: "Max 500 characters"
- 그 밖의 선택 필드: `license`, `metadata`, `allowed-tools` ("Experimental")

**Codex 에만 있는 것** — `agents/openai.yaml`
- interface 항목: `display_name`, `short_description`, `icon_small`, `icon_large`, `brand_color`, `default_prompt`
- `policy.allow_implicit_invocation` (기본값 true)
- `dependencies.tools` (MCP 서버 의존성 선언)

**Claude 규격과의 차이 (추론)**
- 두 필드와 두 숫자(64 / 1024)는 표준과 같다.
- Codex 는 이름 문자 규칙을 표준보다 느슨하게 적용한다.
- `openai.yaml` 은 Claude 에서는 쓰이지 않는 추가 파일일 것이다.

#### 4. 부르는 법과 scripts 실행
- **명시 호출** — "In Codex CLI or the IDE extension, run `/skills` or type `$` to mention a skill."
- **자동 선택** — "Codex can choose a skill when your task matches the skill `description`."
- **자동 선택 끄기** — `allow_implicit_invocation: false` 이면 자동 선택을 하지 않는다. "explicit `$skill` invocation still works"
- **목록 예산**
  - "at most 2% of the model's context window, or 8,000 characters when the context window is unknown"
  - "Codex shortens skill descriptions first"
- **scripts** — `scripts/` 는 "Optional: executable code" 로 적혀 있다.
  - 모범 사례 원문: "Prefer instructions over scripts unless you need deterministic behavior"
  - 실제 실행은 Codex 의 샌드박스와 승인 규칙을 따를 것이다(추론, 문서 확인 안 함).
- **끄기** — `~/.codex/config.toml` 에 `[[skills.config]] path = ".../SKILL.md" enabled = false` 를 넣는다.

#### 5. Claude Code 플러그인 형식을 읽는가
- **마켓플레이스** — ChatGPT 데스크톱 앱은 "a legacy-compatible marketplace at `$REPO_ROOT/.claude-plugin/marketplace.json`" 을 읽는다.
  - 이 문장의 주어는 「The ChatGPT desktop app」 이다. Codex CLI 도 이 파일을 읽는지는 문서에서 못 찾음.
- **manifest** — "OpenAI also accepts legacy and Claude-compatible manifests, but new packages should use this format."
- **제출 포털** — `.claude-plugin/plugin.json` 은 "The portal converts it to `.codex-plugin/plugin.json`."
- **바꿔야 하는 것**
  - `commands/`, `agents/` 는 스킬로 바꿔야 한다.
  - `userConfig` 는 지원하지 않는다.
  - Claude artifact 는 지원하지 않는다.
  - Claude 를 직접 부르는 문구는 "the model" 처럼 중립 표현으로 바꾸라고 한다.
- **Codex 자체 형식**
  - 플러그인 루트의 `plugin.json` 에 `"$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json"` 을 넣고, 같은 루트에 `skills/`, `mcp.json` 을 둔다.
  - OpenAI 전용 설정은 `extensions.com.openai` 에 넣는다.
  - `.codex-plugin/plugin.json` 은 "compatibility fallback" 으로 계속 지원한다.
  - 마켓플레이스 파일은 `$REPO_ROOT/.agents/plugins/marketplace.json` 과 `~/.agents/plugins/marketplace.json` 이다.
  - 설치 자리는 `~/.codex/plugins/cache/$MARKETPLACE_NAME/$PLUGIN_NAME/$VERSION/` 이다.
  - 마켓플레이스 추가 명령: `codex plugin marketplace add owner/repo`
  - 플러그인은 "They aren't available in the IDE extension."
- **가져오기** — Codex CLI 의 `/import` 로 Claude Code 의 Skills, Plugins, 슬래시 명령(Skills 로 바뀜), `settings.json`(`config.toml` 로 바뀜)을 가져온다.

### 출처에 없는 것 / 확인 못 한 것
- **한국어(비ASCII) 이름과 경로** — 문서에 언급이 없다(못 찾음). 코드를 읽고 한 추론은 다음과 같다.
  - `$` 멘션을 읽는 코드는 `is_mention_name_char` 이다. `a-z A-Z 0-9 _ - :` 만 이름 글자로 받는다.
  - 따라서 `$한국어이름` 으로는 명시 호출이 안 될 가능성이 높다(추론).
  - 이름 검사 자체는 글자 수 64 이하만 보므로, 한국어 이름의 스킬도 불러오기는 될 것이다. 자동 선택도 될 것이다(추론).
  - 한국어 경로(`C:\작업\...`)는 코드상 제한을 못 찾음.
  - 이 셋 모두 실제로 실행해서 확인하지 않았다.
- **Codex cloud** — 스킬을 지원하는지 문서에서 못 찾음. 위의 「Standalone skills are available in…」 목록에 cloud 가 빠져 있다.
- **`.agents/skills` 가 생긴 시점** — `.codex/skills` 에서 옮겨 온 버전과 날짜를 못 찾음.
- **Codex CLI 가 `.claude-plugin/marketplace.json` 을 읽는지** — 문서가 이 파일을 읽는다고 적은 주체는 ChatGPT 데스크톱 앱뿐이다. CLI 는 못 찾음.
- **`allowed-tools` 필드** — Codex 가 무시하는지 해석하는지 못 찾음.
- **Codex 이름 규칙** — `parser.rs`, `loader/mod.rs`, `host.rs` 는 읽었다. 하지만 `namespace.rs` 등 다른 파일에 문자나 폴더 이름 일치 검사가 따로 있는지 전부 대조하지는 않았다.
- **검색 요약으로만 본 것** — 「Codex CLI 최신 v0.154.0 (2026-09-09)」 은 직접 확인하지 않았다.
